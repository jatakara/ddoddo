NET-01 · HTTP 전송 및 압축

원인 상태: 관측 확인, 개선 기여도 미분리

구성: 브라우저 → TLS 종단/WAF → WEB 또는 Ingress → 정적 파일

현상·증거: H1 total 2.14~2.39초, H2 1.41~1.47초; TTFB 각각 0.28~0.35초, 0.25~0.26초. 약 40% 개선은 단일 시험의 근사값. 별도 압축 사례 6.2→1.4MB(약 77% 감소).

가설: ALPN, 압축, WAF 검사 후 재압축, 캐시, H1 기준 차이

curl -V
for p in --http1.1 --http2; do curl $p -sS -o /dev/null -w '%{http_version} %{time_starttransfer} %{time_total} %{size_download}\n' https://example.invalid/static/test.js; done
curl -sSI -H 'Accept-Encoding: gzip' https://example.invalid/static/test.js

조치·검증: 동일 객체·캐시·회선에서 반복 측정. 외부 L7 없으면 실제 TLS 종단 WEB/Ingress에서 검토. WAF 전후 Content-Encoding 및 전송량 비교. 이미지에는 엔진, 선언형 설정에는 정책을 관리. SSE 별도 정책.

원복·재발 방지·담당: 이전 압축/HTTP 설정 복원; 정적 파일 캐시·사전압축 검증, 네트워크/WEB 담당

관련 장: 16장

PERF-02 · K8s gzip CPU 병목 및 정적 파일

원인 상태: CPU 제한 영향 관측, 노드별 원인 미확정

구성: Ingress → Nginx Pod → JS

현상·증거: 개발 환경 gzip 7.254초, identity 0.010초; CPU limit 500m→2000m 후 1.108초. 운영 특정 Pod 7.112초, 다른 Pod 약 0.98~1.03초. 별도 브라우저 조사에서 JS 57건 중 52건 비압축; 최소 압축 크기 1MiB 설정 확인. 동일 시험으로 합산 금지.

가설: CPU quota, 압축 레벨 9, 크기 임계값, 노드 경합

kubectl top pods -A --containers
kubectl describe nodes
kubectl exec -n demo deploy/web -- cat /sys/fs/cgroup/cpu.max
kubectl exec -n demo deploy/web -- cat /sys/fs/cgroup/cpu.stat

조치·검증: cgroup v2 기준 throttled_usec/nr_throttled 증가량과 지연 상관 확인. 압축 레벨 4~5 및 임계값 변경은 별도 시험. GitOps desired state와 live 비교, CPU 변경 예외가 ConfigMap에도 적용된다고 가정 금지.

원복·재발 방지·담당: 이전 resource/config 복원, GitOps 동기화 확인; 플랫폼·WEB·개발 담당

관련 장: 7·11·16·37장

AUTH-01 · Android 로그인 및 QR 접근 정책

원인 상태: 조치 후 정상 보고, 직접 인과 미확정

구성: 모바일 또는 PC QR 등록 → Proxy → 인증 AP

현상·증거: 302→403 반복, 일부 UA 시험은 200. Android 관련 UA 허용 확대 후 정상 보고. PC QR 등록 302 사례도 존재.

가설: UA 정책, 경로 매칭, 세션, redirect 생성 주체

curl -sS -D - -o /dev/null -A 'Android WebView' https://example.invalid/login
curl -sS -D - -o /dev/null -A 'Desktop test' https://example.invalid/login

조치·검증: 정상/실패 UA와 Location 비교, 인증 흐름별 최소 경로 예외 검토. UA는 인증 수단이 아니다.

원복·재발 방지·담당: 기존 정책 복원 및 대체 접근 검증; 보안·Proxy·앱 담당

관련 장: 15·17장

AUTH-02 · 모바일 자산 API 200과 인증 오류

원인 상태: 미해결

구성: 앱 → WEB → WAS → 인증/업무 API

현상·증거: 일부 API 200, WAS token/AOP 예외 보고. 원문 스택 및 요청 상관 ID 미확보.

가설: 업무 오류 응답, 토큰 만료, AOP 처리

journalctl -u app --since '10 minutes ago' --no-pager

조치·검증: HTTP 상태와 업무 결과를 분리, 동일 요청 ID의 인증/업무 로그 비교. 토큰 원문 수집 금지.

원복·재발 방지·담당: 변경 전 설정 복원; 개발·WAS 담당

관련 장: 15장

STREAM-01 · 모바일 SSE 401/499

원인 상태: 미해결

구성: 앱 → Proxy → WAF → L7 → UC

현상·증거: 웹 정상, 모바일 499 후 401 관측. 일부 POST 200. FIN 관측 보고. WAF 차단 룰 증거 없음.

가설: 인증 방식, SID 형식, 버퍼링, idle timeout; 499는 연결 종료 관측이지 원인 확정 아님

curl -N -sS --http1.1 --max-time 30 -D - https://example.invalid/test-stream
curl -N -sS --http2 --max-time 30 -D - https://example.invalid/test-stream
ss -tn

조치·검증: 승인된 테스트 인증과 동일 요청으로 각 hop 비교, 첫 이벤트 시간·Content-Type·종료 방향 확인. SSE와 WebSocket Upgrade 구분. WAF 예외는 최소 범위 승인 후 시험.

원복·재발 방지·담당: 이전 경로별 정책 복원; 앱·보안·네트워크 담당

관련 장: 15·17·20장

DB-01 · HR 마감 배치 지연

원인 상태: 미해결

구성: ERP WAS → Oracle → 배치/온라인 거래

현상·증거: 약 20분 배치 중 특정 HR 업무 지연 보고. blocking 조회 결과 없음; 장애 시간대 증적 부족.

가설: TX row lock, 장기 트랜잭션, SQL/I/O, pool 고갈

SELECT sid, serial#, blocking_session, sql_id, event, wait_class FROM v$session WHERE type='USER' AND status='ACTIVE';

조치·검증: 배치 시작 전·중·후 동일 시간축 수집. DBA는 대기·SQL_ID, 개발은 트랜잭션 범위·커밋 검토. 세션 강제 종료 금지.

원복·재발 방지·담당: 튜닝 변경 전 실행계획/설정 보존, 승인된 원복; DBA·개발 담당

관련 장: 15·16장

CAP-01 · 공유 큐 경합 및 성장

원인 상태: 증거 미확보

구성: 생산자 → 공유 큐 → 소비자

현상·증거: 큐 종류·깊이·처리율·전후 수치 미확보.

가설: 도착률이 처리율 초과, 느린 소비자, 재시도 폭증

ss -s
kubectl top pods -A

조치·검증: 큐 깊이·oldest age·arrival/service rate 수집, 업무별 격리와 backpressure 검토. 무조건 소비자 증가 금지.

원복·재발 방지·담당: 기존 동시성 복원; 개발·플랫폼 담당

TUNE-01 · 런타임 경량 튜닝

원인 상태: 검토 사례, 실측 미확보

구성: OS → Nginx/Tomcat → Oracle/Redis

현상·증거: 공통 최적값 및 전후 지표 없음.

가설: CPU·메모리·GC·pool·I/O 경합

vmstat 1 5
free -m
sysctl vm.swappiness vm.vfs_cache_pressure
ss -s

조치·검증: 계층별 baseline 후 한 변수씩 변경. JVM heap과 native memory, Oracle SGA/PGA, Redis eviction 별도 검증.

원복·재발 방지·담당: 설정 백업 및 단계적 원복; OS·미들웨어·DBA 담당

관련 장: 9·16장

K8S-01 · 노드 sizing·서비스 흐름·HA

원인 상태: 설계 검토, 부하 검증 필요

구성: LB → Service → EndpointSlice → Pod → DB

현상·증거: 한 노드 자원 요청/limit 과할당 관측 보고; 사용자 수용량 검증 없음.

가설: requests와 실제 사용량 차이, CPU throttling, 메모리 OOM, 배치 제약

kubectl get nodes
kubectl describe nodes
kubectl get endpointslices -A
kubectl top nodes

조치·검증: allocatable 기준 N+1 및 Pod 배치 시험. limit 합계만으로 부족 판단 금지. Worker 수와 전체 서버 수 구분.

원복·재발 방지·담당: 선언형 리소스 설정 원복; 플랫폼·SA 담당

관련 장: 7·11·12·37장

HA-01 · ERP 단일 서버·L4/L7·DIMS 이중화

원인 상태: 설계 검토, DIMS 증거 미확보

구성: L4/L7 → ERP AP → DB; UC 별도 LB 가능

현상·증거: 단일 서버 요청 사례, 실제 장애/전후 수치 없음. DIMS 지원 토폴로지 미확인.

가설: SPOF, 세션·상태 공유, health check 오판

ss -lnt
curl -sSI https://example.invalid/health

조치·검증: L4 TCP와 L7 HTTP 검사 구분. AP 신규 요청 분산과 DB failover 별도 설계. DIMS 상태·저장소·라이선스 확인 후 이중화 검증.

원복·재발 방지·담당: 이전 LB 정책 복원; SA·네트워크·제품 담당

관련 장: 10·13·39장

CLOUD-01 · 클라우드 라이선스 및 SMTP

원인 상태: 설계 제약, 계약 확인 필요

구성: Cloud VM → DB / SMTP relay

현상·증거: 특정 공급 계약에서 Azure 적용 제한 및 OCI 검토 보고; 일반 Oracle 정책으로 확대 금지. SMTP 25 제한은 구독 유형별 확인 필요.

가설: 라이선스 권리, CPU 단위, egress 정책

getent hosts smtp.example.invalid
nc -vz -w 5 smtp.example.invalid 587

조치·검증: 공급사 서면 확인, 지원 CPU 사양과 실제 성능 검증. 인증 릴레이 지원 여부 확인 후 587/465 검토. 일정·내부 정책 공개 제외.

원복·재발 방지·담당: 기존 승인 메일 경로 복원; 계약·클라우드·앱 담당

관련 장: 7·8·13장
