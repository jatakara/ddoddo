공개 교육용 참조 설계

고객 식별자·비밀번호·내부 IP를 사용하지 않는다. 제품 공식 지원 Matrix, 변경 승인, 보안 정책이 우선한다. 예제 명령은 읽기 전용이거나 실행을 위한 설계 샘플이다.

26.7 수집 계층 아키텍처

Controller → 승인된 읽기 전용 수집기 → 정규화 → 정책 엔진 → 증거 저장소 → 보고서로 분리한다. 수집기는 정책을 평가하거나 변경하지 않는다. 평가 엔진은 수집 결과를 변경하지 않는다.

26.8 Linux 점검

/etc/os-release, uname, sysctl -n, timedatectl, /proc/<PID>/limits, ss -lnt 등을 최소 권한으로 수집한다. /proc 값은 실행 중 프로세스에 적용된 실제 한도를 보여주므로 로그인 셸의 ulimit 값과 구분한다. SELinux·THP·HugePages는 무조건 변경하지 않고 제품/DB 지원 조건을 확인한다.

26.9 Kubernetes 점검

Namespace, Deployment, Requests/Limits, Ready 상태, PodDisruptionBudget, RBAC, NetworkPolicy, 이미지 digest, PVC 및 StorageClass를 읽기 전용 API로 조회한다. NetworkPolicy 객체 존재만으로 격리가 보장되지는 않으며 CNI 구현 및 실제 연결 시험이 필요하다.

26.10 DB 점검

Oracle/Tibero의 계정 권한, 백업 최근 성공, 세션·대기·스토리지 사용량을 DBA 승인된 조회 계정으로 확인한다. DB 파라미터는 엔진·버전·라이선스·워크로드별로 다르므로 범용 정답값을 강제하지 않는다. SQL 출력에서 업무 데이터·개인정보를 제외한다.

26.11 Drift의 우선순위

드리프트 위험도는 심각도 × 노출 범위 × 업무 영향 × 변경 시점으로 평가한다. 보안 취약 구성이라도 긴급 자동 변경으로 장애를 유발할 수 있으므로 조치 긴급도와 자동 실행 허용 여부를 별도 판단한다.

# 교육용 읽기 전용 명령; 변경 작업 없음
cat /etc/os-release
sysctl -n vm.swappiness
timedatectl show -p NTPSynchronized
cat /proc/<PID>/limits
kubectl get deploy,pdb,networkpolicy -n <namespace>
kubectl auth can-i get pods -n <namespace> --as=<readonly-service-account>

26.12 증거와 판정 재현성

수집 시각(UTC), 자산 식별자(가명), 정책 버전, 수집기 버전, 결과 해시, 판정 사유, 예외 ID를 남긴다. 원시 로그와 비밀정보를 공개 Git 저장소에 올리지 않는다.
