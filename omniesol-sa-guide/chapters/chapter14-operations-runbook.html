14.7 일일·주간·월간 점검

운영 점검은 체크 여부가 아니라 기준선, 편차, 조치 증빙을 남기는 절차다. 계측 공백을 정상으로 취급하지 않는다. 아래 주기는 교육용 예시이며 계약과 업무 중요도에 맞춰 조정한다.

주기점검 항목판정·증빙
일일ERP 로그인·조회·저장, UC 로그인·메뉴·실시간 기능, 성공률·p95사용자 여정 시험, 대시보드 스냅샷
일일DB 백업, 배치, 큐 적체, 디스크 여유, Pod Ready/OOM실패 건수·이벤트·추세
주간오류 예산, 인증서 만료, WAF 예외, 계정·권한, 패치 계획예외 만료일·담당자·변경 티켓
월간복원 표본 시험, 용량 증가율, 반복 장애 원인복원 시간·정합성·개선 계획
분기/정책 기준DR, 노드 장애, 원복 및 비상연락 훈련실패 주입 범위·승인·결과

14.8 장애 등급과 에스컬레이션

장애 등급은 CPU 사용률이 아니라 업무 영향, 사용자 범위, 데이터 무결성·보안 위험으로 판정한다. 계약상 기준이 있으면 우선 적용한다.

등급대표 상황필수 대응
P1핵심 업무 전면 중단, 광역 UC 장애, 데이터 손상 의심Incident Commander 지정, 위험 변경 중지, 업무·DB·보안 공동 대응
P2중요 기능 부분 중단, 우회 불가, 영향 확대영향 범위 확인, 승인된 원복·우회, 담당 조직 호출
P3제한적 오류, 우회 가능, 경미한 성능 저하티켓·재현·계획 조치

장애 발생·탐지·완화·정상화 시각을 분리하고, 확인된 사실과 추정 원인을 별도 기록한다.

14.9 공통 장애 Runbook

1. 감지: 사용자 신고 또는 SLO 경보
2. 영향: ERP/UC, 내부/외부, 기능·사용자·발생 시각
3. 변경: DNS·TLS·WAF·Proxy·배포·DB 이력
4. 완화: 승인된 원복·우회·격리
5. 진단: DNS → TCP → TLS → Proxy → WAS/Pod → DB/Queue
6. 검증: 실제 로그인·조회·저장·실시간 기능
7. 종료: 데이터 정합성·SLO·보안 영향·PIR
증상첫 확인오진 방지
접속 불가DNS·TLS·WAF/LBDNS 성공이 HTTPS 성공은 아님
ERP 저장 지연WAS Pool·DB Lock/Wait·Storage낮은 CPU도 DB 병목 가능
UC 메뉴만 실패SSO·API·Cookie/CORS·Split DNS로그인 성공만으로 기능 정상 아님
실시간 스트림 중단SSE/WebSocket·버퍼링·WAF·timeoutHTTP 200만으로 검증 불가
K8s 503Ingress·Service·EndpointSlice·ReadyRunning과 Ready 구분

운영 변경·재시작·방화벽 정책 수정은 영향 평가, 승인, 원복 계획 없이 실행하지 않는다. 로그의 인증 정보·개인정보를 마스킹한다. 상세 계층별 진단은 15장을 참고한다.

14.10 변경관리와 기술적 부채

선택장점위험통제
공통 모니터링상관관계 분석권한 집중·단일 장애점RBAC·HA·외부 합성 시험
자동 복구MTTR 단축반복 재시작·증거 소실횟수 제한·중단 조건·검증
독립 배포변경 영향 격리API·인증 버전 불일치호환성 매트릭스·계약 테스트
수평 확장처리량 증가DB·큐 병목 잔존종단 간 부하 시험·N+1

무기한 WAF 예외, 임시 hosts, 공용 관리자 계정, 복원 미검증, 문서 없는 긴급 변경은 기술적 부채다. 예외마다 담당자·만료일·제거 계획을 지정한다.

14.11 백업·복원·DR 검증

백업 성공은 복원 성공의 충분조건이 아니다. 격리된 시험 환경에서 DB·첨부·설정·암호화 키의 일관성을 검증하고 RPO/RTO를 실제 측정한다.

단계합격 기준증빙
백업 선택시점·보존·무결성 확인백업 ID·체크섬
DB/파일 복원오류 없음·데이터 정합성복원 로그
업무 검증ERP 조회/저장·UC 인증/기능 정상시험 케이스
RPO/RTO승인 목표 이내시작·완료·복원 시점
보안시험 데이터 보호·최소 권한접근·파기 기록

HA는 일부 구성요소 장애 대응이고, DR은 광역 장애·데이터 손실로부터의 복원 체계다. 서로 대체하지 않는다.
