공개 교육용 참조 설계

공식 제품 설치 사양이 아니다. 모든 수치와 경로는 교육용 예시이며 실제 적용은 지원 버전, 계약, 변경 승인 및 보안 정책을 우선한다.

33.1 Readiness와 설치 완료의 차이

Readiness는 설치에 필요한 전제조건을 충족했다는 증거 기반 판정이다. 설치 성공이나 업무 서비스 정상화와 동일하지 않다. 7장의 Sizing Matrix, 8장의 설치 준비, 30장의 책임 경계를 하나의 입력 계약으로 결합한다. 설치 프로그램은 사양을 추측하거나 불합격 환경을 임의로 변경하지 않는다.

33.2 배포 유형별 검증 프로파일

유형검증 대상주의점
ERP 단독WEB/WAS, DB, 연계DB 라이선스와 I/O
UC 단독서비스 노드, 저장소, 외부 접속메일 기능 사용 시 별도 경로
통합형ERP·UC 및 공용 자원자원 경쟁, 장애 전파
분리형각 시스템 및 연계 경로인증·DNS·TLS 경계

실제 구성 요소는 승인된 버전별 지원 Matrix에서 결정한다. Kubernetes 사용 여부도 배포 프로파일의 명시적 입력이다.

33.3 CPU와 메모리 자동 수집

lscpu
free -b
cat /proc/meminfo
cat /proc/swaps
cat /etc/os-release
uname -r

물리 코어, 논리 CPU, VM vCPU를 구분한다. 가상화 환경은 할당량뿐 아니라 예약·오버커밋·NUMA 정책을 확인한다. MemAvailable은 현재 상태이며 설치 후 최대 사용량을 보장하지 않는다. DB SGA/PGA, JVM heap 외 native memory, OS와 파일 캐시, 컨테이너 예산을 중복 없이 합산한다.

예: 64 GiB 서버에서 DB 24, AP 16, 기타 6, OS 6, 여유 12 GiB를 할당하는 가상 계획은 합계 64 GiB다. 이는 공식 권장값이 아니며 실제 피크 측정과 지원 정책으로 검증한다.

33.4 스토리지와 파일시스템

lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
findmnt
 df -hT
 df -i

DB data, redo, archive, backup 및 애플리케이션 파일을 분류한다. 여유 용량뿐 아니라 inode, mount 옵션, 소유권, 장애 도메인, IOPS·지연을 확인한다. 논리 볼륨 분리만으로 물리 I/O가 격리되지는 않는다. 운영 디스크에 fio 쓰기 시험을 자동 수행하지 않는다. 백업은 동일 장애 도메인 외부에 저장한다.

33.5 OS·Kernel·계정 검증

sysctl vm.swappiness vm.vfs_cache_pressure
getenforce
systemctl is-active firewalld
rpm -q openssh-server
id
ulimit -n

RHEL 지원 버전, 커널, 필수 RPM, 서비스 계정, SELinux·방화벽 상태를 승인된 기준과 대조한다. ulimit은 현재 셸 값이므로 실제 서비스의 systemd LimitNOFILE과 별도로 확인한다. swap, THP, HugePages는 DB와 Kubernetes의 버전별 요구사항을 구분한다. 점검 실패를 이유로 보안 기능을 일괄 비활성화하지 않는다.

33.6 N+1 및 증설 판단

동일 노드 4대에서 한 대 장애를 가정하면 가용 노드는 3대다. 노드당 예약 제외 가용 CPU 12코어, 목표 사용률 70%이면 장애 후 계획 용량은 3×12×0.7=25.2코어다. 피크 요구량 28코어라면 정상 상태에서 여유가 있더라도 N+1 기준은 실패한다.

CPU 모델만으로 처리량을 보증할 수 없고, 메모리·스토리지·Pod 배치 제약도 독립 검증한다. 가용성 확대와 유휴 비용의 Trade-off를 ADR로 기록한다.
