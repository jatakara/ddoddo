17.13 보안 이벤트와 서비스 지표 연계

보안 이벤트는 서비스 장애와 연결된다. SSO 토큰 검증 실패는 로그인 오류율 증가로, WAF 오탐은 HTTP 403 증가로 나타날 수 있다. 요청 ID·시각·서비스명·결과로 관제와 운영 증거를 연계한다.

계층관측 이벤트민감정보 주의

WAF/Proxy차단률·정책 변경·4xx/5xx쿠키·민감 Query
WAS/API권한 거부·업무 감사요청·응답 본문/첨부

백업실패·삭제·권한 변경·복원 오류암호화 키·저장소 상세

로그 수집 자체가 정보 유출 경로가 되지 않도록 마스킹, 보존 기간, 접근권한, 암호화와 감사를 적용한다. NTP 동기화는 사건 순서의 신뢰성을 높인다.

17.14 위험 기반 패치·취약점·예외 관리

CVSS 점수만으로 패치 순서를 결정하면 실제 위험을 놓칠 수 있다. 외부 노출, 실제 악용 징후, 데이터 중요도, 제품 지원성, 대체 통제, 업무 중단 비용을 함께 평가한다.

항목질문증거
노출도인터넷에서 직접 접근 가능한가?접속 흐름·방화벽 정책
영향거래 데이터 유출·중단 위험은?업무 중요도·데이터 분류
악용 가능성실제 공격 징후나 공식 보안 공지가 있는가?관제 로그·벤더 공지
지원성OS/DB/WAS 패치를 제품이 지원하는가?공식 호환성 Matrix
운영 영향패치 후 p95·배치·HA·복구 목표 충족?시험·원복 결과
  • 취약점에 영향을 받는 버전과 실제 사용 모듈을 확인한다.
  • 위험과 대체 통제를 기록하고 책임자·기한을 지정한다.
  • 비운영 회귀·성능·복구 시험 후 운영에 반영한다.
  • 임시 예외는 만료·재검토·폐기 기한을 명시한다.
기술적 부채

취약점마다 WAF 예외와 방화벽 우회만 추가하면 공격 표면이 누적된다. 임시 완화 정책을 영구 대책으로 방치하지 않는다.

17.15 보안 사고 대응 Runbook

가상 사례: ERP 연계 서비스 토큰이 운영 로그에 기록된 사실을 발견했다. 즉시 전체 시스템을 재시작하면 증거가 사라지고 중단이 확대될 수 있다. 유효 토큰 여부, 노출 범위, 접근 흔적을 평가하고 승인된 억제·복구를 진행한다.

단계수행 활동주의
탐지로그·경보·신고 시각 기록민감정보를 티켓에 원문 첨부 금지
평가토큰 유효성·권한·접근 흔적 확인미확정 원인 단정 금지
억제승인된 키 폐기·접속 정책 강화의존 서비스 확인 없는 전체 차단
복구새 키 적용·로그인/저장/API 시험Pod Running만으로 완료 판단 금지
사후노출 원인·탐지 보강·보고증거 보존·신고 의무 검토 누락

개인정보 침해 통지 및 신고는 적용 법률과 고객 보안조직 절차에 따라 판단한다. 본 가이드는 법률 자문이나 사고 대응 권한 위임 문서가 아니다.

17.16 하드닝 적용 후 업무·보안 회귀 시험

보안 강화의 성공 기준은 허용 업무는 성공하고 비허용 동작은 거부되는 것이다. 노드 장애와 Failover 중에도 정책이 유지되는지 확인한다.

시험 결과서

시험 시각·정책 ID·테스트 계정 유형·허용/거부 결과·사용자 영향·원복 조건을 기록한다. 실제 비밀값·개인정보·내부망 상세는 공개 문서에 포함하지 않는다.

17.17 운영 RACI와 예외 승인

업무SA/TA운영팀보안팀제품·DB 담당
신뢰 경계 설계RCA/CC
OS·Proxy 정책CRA/CC

보안 예외대안 제시영향 평가승인 주관지원 확인
사고 대응아키텍처 영향서비스 복구사고 총괄제품 분석

R(수행), A(최종 책임), C(협의)는 계약과 조직 정책에 맞게 재정의한다. 표는 역할 협의 예시이며 고객·공급자의 법적 책임을 규정하지 않는다. 위험 수용은 기술자 개인 판단으로 대신할 수 없다.
