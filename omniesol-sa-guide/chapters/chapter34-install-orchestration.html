공개 교육용 참조 설계

실제 OmniEsol 설치 명령 또는 지원 사양이 아니다. 제품 공식 지원 문서, 보안 정책 및 변경 승인을 우선한다. 모든 주소와 수치는 교육용 예시다.

34.1 GUI와 실행기의 분리

Windows GUI는 환경 입력, 계획 확인, 진행률 및 오류 표시를 담당한다. 실제 실행기는 승인된 작업만 수행하는 별도 프로세스로 구성한다. GUI 종료를 설치 취소로 간주하지 않는다. 중앙 실행기는 다수 현장에 유리하지만 접근 권한이 집중되므로 고객별 실행 영역을 분리한다. 로컬 실행기는 초기 비용이 낮으나 PC 종료 및 네트워크 단절에 대비한 영속 상태 저장이 필요하다.

Windows GUI → Plan / Approval → Durable Job Store
                                     ↓
                              Isolated Runner
                                     ↓ SSH / API
                              Linux / DB / K8s
                                     ↓
                              Evidence Store

34.2 설치 의존성 DAG

DAG(Directed Acyclic Graph)는 작업의 선후 관계를 표현한다. 순환 의존성은 계획 생성 단계에서 거부한다. 서로 다른 서버의 독립 작업만 병렬화하고 공용 저장소, DB 스키마, 클러스터 변경은 자원 잠금으로 직렬화한다.

Readiness → Artifact verification → OS preparation
                                        ├─ DB → ERP WAS → ERP WEB
                                        └─ K8s → UC dependencies → UC workloads
ERP / UC readiness → Integration (해당 시) → Business acceptance

위 순서는 개념 예시이며 제품의 실제 설치 순서와 지원 매트릭스를 우선한다. UC가 별도 DB를 요구하면 해당 의존 노드를 추가한다.

34.3 SSH와 아티팩트 신뢰

SSH 호스트 키는 별도의 신뢰 가능한 경로로 등록한다. 최초 접속 성공만으로 서버 신원을 인정하지 않는다. 단기 키 또는 제한된 전용 계정과 명령별 sudo 정책을 사용한다. 배포 파일은 서명 또는 신뢰 가능한 승인 manifest와 SHA-256을 대조한다. 해시만으로 발행자 신원을 증명할 수는 없다.

ssh -o BatchMode=yes -o StrictHostKeyChecking=yes \
  -o UserKnownHostsFile=./approved_known_hosts \
  installer@erp.example.invalid -- 'id'
sha256sum -c approved-artifacts.sha256

교육용 읽기 명령이며 실제 주소·계정·권한은 승인된 값으로 대체한다. 개인키와 응답 파일은 로그나 Git에 기록하지 않는다.

34.4 작업 계약과 승인

step_id: db.software.install
target: lab-db-01
requires: [os.ready, artifacts.verified]
timeout_seconds: 3600
retry: reconcile_first
lock: lab-db-01/oracle-home
postcheck: db.software.version
rollback: manual_review

실행 명령은 검토된 Adapter에서 제공한다. 사용자 입력을 셸 문자열로 이어 붙이지 않는다. 계획 digest와 대상, 지원 버전, 아티팩트, 승인 유효기간을 묶고 실행 직전 재확인한다. 3600초는 예시일 뿐 실제 제한시간은 시험으로 결정한다.

34.5 상태 모델과 동시 실행

상태의미
PENDING / RUNNING대기 / 실행 중
VERIFIED사후 조건 확인 완료
FAILED실패 확인, 원인 분석 필요
UNKNOWN실제 실행 결과 불명, 재조사
BLOCKED의존성 또는 승인 미충족

실행 기록은 원자적으로 갱신하고 심박 및 lease를 관리한다. lease가 만료되어도 기존 원격 프로세스의 종료를 보장하지 않으므로 무조건 재할당하지 않는다. 대상에서 fencing을 지원하지 않으면 작업 상태를 조사하고 수동 승인 후 재개한다.

34.6 실행 엔진 설계 체크리스트

  • 계획 DAG 순환 검사와 버전 고정
  • 승인 범위와 SSH 호스트 키 검증
  • 대상 단위 잠금 및 동시 실행 상한
  • GUI 종료 후 작업 상태 재조회
  • 로그 마스킹, 보존 기간, 작업 ID 추적
  • 사후 조건 불충족 시 후속 작업 차단

처음부터 분산 Queue를 도입할 필요는 없다. 단일 실행기와 영속 저장소에서 실패 복구를 검증하고, 동시 구축 수요가 증가할 때 HA 및 분산 실행으로 확장한다.
