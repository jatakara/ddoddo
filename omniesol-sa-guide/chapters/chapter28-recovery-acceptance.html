공개 교육용 참조 설계

실제 고객·내부 시스템 정보 및 인증정보를 포함하지 않는다. 시험은 격리된 실습 환경에서 수행한다. 수치와 합격선은 예시이며 실제 지원 사양·계약·운영 정책이 우선한다.

28.13 복구 우선순위

신규 변경 실행 중단 → 감사·승인 상태 확인 → Queue/State DB 복구 → Controller 복구 → Collector 재동기화 → 읽기 전용 진단 검증 → 승인형 실행 재개 순서로 진행한다. 자동화 플랫폼 복구가 ERP·UC 서비스의 무조건적 재시작을 유발해서는 안 된다.

28.14 RTO·RPO 측정

RTO는 플랫폼의 합의된 업무 기능이 정상화될 때까지의 실제 경과 시간이다. RPO는 상태 DB·승인·감사 데이터의 허용 손실 시점 차이다. 교육용 목표 RTO 60분/RPO 5분을 설정하더라도 감사 이벤트 무손실이 별도 요구라면 RPO만으로 충족을 판단할 수 없다.

28.15 테스트 Matrix

Controller 1대 종료: 신규 승인 작업 중복 실행 0건 / Queue 재기동: 만료 job 실행 0건 / Policy 서버 장애: 신규 변경 DENY / Audit 쓰기 장애: 신규 변경 0건 / Runner timeout: UNKNOWN 후 상태 재조회 / Collector 장애: 자산 상태 UNKNOWN / 테넌트 A 과부하: B의 SLO 유지. 각 시험의 증거는 job ID·정책 버전·타임스탬프·감사 이벤트로 연결한다.

28.16 합격 판정과 예외

PASS는 측정값과 로그로 증명된 경우에만 부여한다. FAIL은 합격 기준 위반, UNKNOWN은 증거 부족 또는 측정 불가다. 승인 없는 변경 1건, 감사 누락, 테넌트 간 권한 침범은 성능 목표 충족과 관계없이 No-Go로 처리한다. 위험 수용 예외는 책임자·만료일·완화책을 명시한다.

28.17 운영 인수인계

운영팀에 구성 BOM, 의존성 맵, 권한/RACI, 백업·복구 절차, 장애 대응 연락망, 대시보드, 경보 임계치, 변경 동결 정책, 복구 훈련 증거를 전달한다. 신규 운영자가 테스트 환경에서 승인 중단·복구·감사 조회를 직접 시연하도록 한다.

28.18 개선 우선순위와 비용

복구 실패 위험 × 영향도 × 발생 가능성을 우선 평가하고, 대기열 수평 확장·상태 저장소 HA·감사 내구성 개선 비용을 비교한다. 무조건적인 Active-Active보다 명확한 실패 격리·복구 가능성이 비용 효율적일 수 있다. 개선 후 동일 시험을 반복하여 효과를 확인한다.

현장 아키텍처 노트

Load Generator → API Gateway → Controller → Policy Engine
                                      ↓
                                 Durable Queue
                                      ↓
                              Test Runner / Mock Target
                                      ↓
                              Evidence + Audit Store

Failure injection: Controller / Queue / Policy / Audit
Safety gate: 승인 무결성 + 실행 중복 방지 + 감사 기록

확장 시 Worker 증설보다 상태 저장소, 큐 파티션, 외부 API rate limit, 테넌트별 공정 스케줄링의 병목을 먼저 확인한다. TLS, 최소 권한, 단기 자격증명, 비밀정보 마스킹, 감사로그 변조 탐지를 시험 범위에 포함한다.
