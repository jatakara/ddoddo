공개 교육용 참조 설계

고객 식별자·비밀번호·내부 IP를 사용하지 않는다. 제품 공식 지원 Matrix, 변경 승인, 보안 정책이 우선한다. 예제 명령은 읽기 전용이거나 실행을 위한 설계 샘플이다.

26.13 실행 상태 머신

DETECTED → TRIAGED → PROPOSED → APPROVED → PRECHECKED → EXECUTING → VERIFYING → CLOSED로 전이한다. 거부·시간 초과·검증 실패는 ABORTED 또는 ROLLBACK_REQUIRED로 종료한다. 승인은 실행 대상·명령·시간창·만료일에 결속한다.

26.14 승인과 권한 분리

진단 주체는 운영 변경 권한을 갖지 않는다. 실행 계정은 명령 Allowlist, 대상 범위, 단기 자격증명, 동시 실행 제한을 적용한다. 관리자 승인 없이 AI가 명령을 자유 생성·실행하는 구조는 금지한다.

26.15 Runbook의 필수 필드

Runbook ID, 적용 버전, 변경 목적, 영향 서비스, 사전 조건, 백업/복구 가능성, 실행 명령, 예상 시간, 검증 기준, 중단 조건, 원복 절차, 담당자·승인자·증거 링크를 작성한다.

26.16 장애 방지 장치

동일 대상 중복 실행을 막는 idempotency key, 잠금, 타임아웃, 단계별 최대 재시도, 변경 창, canary 검증을 둔다. DB 스키마 변경·데이터 삭제·보안 정책 완화는 일반 자동 복구 대상에서 제외한다.

26.17 현장 실습과 Go/No-Go

가상 AP 서버의 swappiness Drift를 탐지한다. 증거 수집 → 정책 비교 → 변경 제안서 → 관리자 승인 → 비운영 환경 리허설 → 사후 검증을 수행한다. 승인 전에는 sysctl -w를 실행하지 않는다. 재부팅 후 영속성도 별도 검증한다.

runbook_id: RB-OS-001
mode: approval_required
target: role=ap, environment=stage
precheck: [asset_verified, support_matrix_checked, backup_reviewed]
approval: {role: operations_owner, ttl_minutes: 30}
execution: {allowlisted_action: apply_sysctl_profile, timeout_seconds: 120}
verification: [sysctl_runtime, persistent_config, application_smoke_test]
rollback: {action: restore_previous_profile, approval_required: true}
audit: {redact_secrets: true, immutable_log: true}

26.18 운영 KPI와 다음 장

점검 커버리지, UNKNOWN 비율, 오탐률, 승인 대기 시간, 변경 실패율, 원복 성공률, 예외 만료 건수를 추적한다. 다음 27장은 자동화 플랫폼 운영 모델과 보안·확장성·비용을 다룬다.
