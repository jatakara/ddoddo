실제 제품의 공식 설치·지원 사양이 아니다. 예시 수치·절차는 가상이며 실제 적용은 계약·보안 정책·지원 Matrix·변경 승인을 우선한다.

23.1 설치 완료와 운영 준비 완료의 차이

제품 설치가 끝났다는 사실은 운영 준비 완료를 의미하지 않는다. 설치 완료는 바이너리·설정·서비스가 배치되었다는 상태이며, 운영 준비 완료는 고객이 승인한 업무 흐름을 목표 성능·보안·복구 조건 안에서 수행할 수 있다는 상태다. 이 둘을 혼동하면 검수 이후 첫 장애에서 책임과 조치 범위가 불명확해진다.

게이트확인 질문대표 증거
설치 완료지원 버전과 구성 요소가 설치되었는가?BOM, 설치 로그, 서비스 목록
기능 검수업무 사용자가 실제 시나리오를 완료하는가?시나리오별 결과·화면·요청 ID

제품 버전별 공식 설치·지원 Matrix와 고객 계약의 인수 기준이 이 교육용 예시보다 우선한다.

23.2 FAT와 SAT의 역할

FAT(Factory Acceptance Test)는 고객 운영 현장에 적용하기 전에 준비된 구성이나 기능을 시험하는 활동이다. SAT(Site Acceptance Test)는 실제 설치 현장의 네트워크·인증·보안·연계·업무 조건에서 요구사항을 검증한다. 계약에 따라 용어와 수행 주체가 달라질 수 있으므로 시험 계획서에 정의를 명시한다.

항목FAT 예시SAT 예시
목표구성품과 기능의 사전 적합성현장 환경의 실제 업무 적합성
환경랩/검증 환경승인된 고객 설치 환경
검증 대상지원 버전, 서비스 기동, 기본 API내·외부 DNS, TLS, SSO, 방화벽, DB, 백업
부하기초 처리량·오류 재현업무 피크·네트워크 지연·배치 동시성
결과출고·설치 승인 근거운영 수용 승인 근거

FAT를 통과해도 고객사 Proxy에서 Host 헤더가 변경되거나 인증서 체인이 달라지면 SAT가 실패할 수 있다. 따라서 시험 결과는 환경 식별자와 함께 보존한다.

23.3 검수 Traceability Matrix

모든 검수 항목은 요구사항 ID와 연결되어야 한다. 시험 담당자와 증거가 없는 “정상” 표시는 수용 근거로 부족하다. 요구사항 → 시험 사례 → 증거 → 결함 → 재시험 → 승인까지 추적한다.

요구 ID시험 시나리오합격 기준(가상)증거/담당
REQ-001ERP 로그인·전표 조회승인 계정으로 정상 조회테스트 로그·업무 담당
REQ-002외부 모바일 인증허용 경로 성공, 미인가 API 거부HTTP 응답·보안 담당
REQ-003UC 메시지·파일저장·재접속·다운로드 정상업무 증거·운영 담당
REQ-004백업 후 복구합의한 RTO/RPO와 데이터 정합성 충족복구 로그·DBA
REQ-005노드 1대 장애합의한 SLO 내 핵심 업무 지속장애 시험·SA

합격 기준의 수치는 계약·업무 목표에 따라 결정한다. 위 표는 가상 예시이며 OmniEsol의 공식 성능 보증 수치가 아니다.

23.4 ERP·UC 업무 검수 시나리오

단순히 메인 화면의 HTTP 200을 확인하면 업무 중단을 놓칠 수 있다. ERP는 조회·등록·승인·배치·파일·보고서를, UC는 로그인·메시지·파일·실시간 알림·모바일 접속을 사용자 관점에서 검증한다.

서비스정상 경로실패/예외 경로
ERP로그인→목록→등록→조회→권한별 승인권한 없는 승인 거부·중복 제출
UC로그인→메시지→첨부→재접속세션 만료·파일 크기 제한
모바일인증→기기 등록→기능 사용만료 토큰·미인가 단말
외부 접속외부 DNS→TLS→Proxy→서비스내부 전용 API 접근 거부
배치/연계배치 실행→결과 조회→로그 확인재처리·중복·시간 초과
보안 주의

인증 성공만 시험하지 말고 역할별 권한 거부와 직접 API 호출의 인가 검증을 포함한다. 실제 개인정보·인증 토큰은 검수 증거에 남기지 않는다.

23.5 비기능 검수와 장애 주입

성능 검수는 사용자 수만 제시하지 않고 부하 모델, 데이터 규모, 관측 시간, 백엔드 상태, p95/p99, 오류율을 기록한다. 고가용성은 서버 수가 아니라 장애 주입 후 업무 성공으로 확인한다.

  • 성능: 정상·피크·배치 동시 실행 조건과 p95/p99·오류율을 측정한다.
  • 보안: 인증서, 최소 권한, 외부 노출 경로, 취약점 예외 승인 상태를 확인한다.
  • 가용성: 노드·Proxy·Pod·DB 등 허용된 범위의 장애를 주입하고 복구를 측정한다.
  • 데이터: DB와 첨부파일·세션 저장소의 정합성 및 백업 복원을 검증한다.
  • 확장성: N+1 자원, CPU/메모리 Requests, DB 연결 풀 및 스토리지 성장 여유를 점검한다.
시험 안전

장애 주입은 별도 시험계획과 승인된 유지보수 창에서 수행한다. 운영 데이터에 대한 파괴적 테스트는 수행하지 않는다.

승인서에는 “일부 실패하였으나 정상” 같은 모호한 문구를 쓰지 않는다. 미해결 결함은 운영 수용의 조건부 승인 또는 No-Go 사유로 명확히 분류한다.
