공개 교육용 참조 설계

공식 제품 설치 사양이 아니다. 모든 수치와 경로는 교육용 예시이며 실제 적용은 지원 버전, 계약, 변경 승인 및 보안 정책을 우선한다.

33.7 네트워크 경로와 L4/L7 경계

외부 사용자 → 방화벽 → L4/L7 또는 Proxy → WEB/WAS
                                             ├→ DB
                                             └→ UC 연계
관리망 → 승인된 설치 Runner → 대상 노드

L4는 TCP 연결을, L7은 HTTP 호스트·경로 등 애플리케이션 정보를 기반으로 전달할 수 있다. TLS 종료 지점과 원본 IP 전달 방식, 세션 유지, 헬스체크 경로를 명시한다. 실제 토폴로지와 제품 지원 여부를 확인하며 DB를 외부 사용자망에 직접 노출하지 않는다.

33.8 DNS·NTP·TLS 검증

getent ahosts app.example.invalid
chronyc tracking
chronyc sources -v
ip route
ip -br address

예시 도메인은 실제 승인된 FQDN으로 치환한다. 내부와 외부 DNS, 인증서 SAN, 체인, 유효기간 및 시간 동기화 상태를 각각 확인한다. TLS 시험은 인증서 검증을 생략하지 않는다. 시간 편차 임계값은 인증·클러스터 요구조건으로 정한다.

33.9 방화벽 연결 Matrix

출발목적프로토콜/포트 예시검증
사용자서비스 VIPTCP 443HTTPS 및 인증서
APDB ListenerTCP 1521TCP 및 DB 연결
노드DNSUDP/TCP 53이름 해석
관리 Runner관리 대상TCP 22승인된 SSH

모든 포트는 일반적 예시이며 실제 설치값이 아니다. 출발지에서 목적지 방향으로 제한된 연결 시험을 수행한다. TCP 성공은 애플리케이션 성공을 보증하지 않는다. nc -vz -w 3 HOST PORT를 승인된 경로에 한해 사용한다. 미사용 경로는 자동 허용하지 않는다.

33.10 Oracle 설치 적합성

DB 버전·RU·OS 인증 조합, 설치 계정, 그룹, 필수 RPM, 파일시스템, 메모리/공유메모리, Listener와 라이선스 조건을 확인한다. 기존 DB가 있으면 설치 대상과 분리하고 덮어쓰기를 차단한다.

-- 승인된 기존 DB에서 읽기 권한으로 수행
SELECT banner FROM v$version;
SELECT name, open_mode FROM v$database;
SELECT name, value FROM v$parameter
 WHERE name IN ('sga_target','pga_aggregate_target','processes');

신규 서버에 DB가 없는 경우 SQL 점검은 NOT_APPLICABLE이다. 기존 DB 접근 실패는 UNKNOWN이며 정상 판정으로 대체하지 않는다.

33.11 Kubernetes 설치 전·후 검증

설치 전에는 지원 OS·런타임·커널 모듈, 노드 간 라우팅, Pod/Service CIDR 충돌, MTU, 저장소 요구조건, 이미지 접근 및 시간 동기화를 확인한다. CNI별 포트와 encapsulation은 실제 지원 문서에 맞춘다.

# 기존 클러스터에 한해 제한된 권한으로 수행
kubectl get nodes
kubectl get storageclass
kubectl get pods -n kube-system
kubectl auth can-i get nodes

Ready 노드 수만으로 충분하지 않다. requests/limits, allocatable, taint, affinity, PVC 바인딩, 장애 후 스케줄링과 접근권한을 확인한다. Secret 전체 조회는 수집 범위에서 제외한다.

33.12 오프라인 설치와 공급망

폐쇄망에서는 OS RPM, DB 설치 미디어, 컨테이너 이미지와 의존성 목록을 승인된 Manifest로 준비한다. SHA-256은 신뢰된 기준값과 대조할 때 무결성을 확인할 수 있다. 해시만으로 발행자 인증이 되지는 않으므로 서명 검증 및 반입 승인도 필요하다.

sha256sum -c approved-artifacts.sha256

저장소 인증정보를 로그에 출력하지 않고, 제품 라이선스 및 재배포 조건을 준수한다. 온라인 방식은 최신 의존성 접근이 쉽지만 외부 공급망과 네트워크 의존성이 생긴다. 오프라인 방식은 재현성이 높지만 보안 업데이트 반입 절차가 필요하다.
