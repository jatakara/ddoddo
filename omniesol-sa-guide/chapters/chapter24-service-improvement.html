24.13 월간 서비스 리뷰 운영

서비스 리뷰는 장애 보고서를 읽는 회의가 아니라, 서비스 목표의 충족 여부와 다음 조치를 결정하는 회의다. 업무 Owner, SA, 운영팀, DBA, 네트워크·보안 담당의 역할을 명시하고 주요 변경·복구 시험·오류 예산을 검토한다.

순서입력결정
1. 품질업무 SLI·SLO·데이터 누락목표 미달 원인과 소유자
2. 장애중요 사고·반복 원인·PIR재발 방지와 검증 기한
3. 변경배포 실패·원복·패치 이력변경 통제 개선
4. 용량p95/p99, DB 대기, K8s N+1, 성장률증설 또는 튜닝 계획
5. 보안·복구취약점·권한·백업/DR 시험미해결 위험 수용/차단
6. 투자예상 비용·효과·불확실성분기 백로그 우선순위

24.14 분기 개선 사이클: Plan–Do–Check–Act

분기 개선은 단일 성능 숫자의 개선보다 운영 체계의 지속 가능성을 목표로 한다. 예를 들어 UC SSE 끊김이 감소했더라도 Proxy Timeout만 늘려 백엔드 커넥션이 고갈되면 개선으로 인정하기 어렵다.

  • Plan: 개선 목표와 측정 가능한 성공 기준, 책임자, 기간을 기록한다.
  • Do: DEV/QA 검증과 변경 승인 후 제한된 범위에 적용한다.
  • Check: 업무 SLI·오류율·보안·비용·복구 가능성을 함께 비교한다.
  • Act: 효과가 입증되면 표준 구성과 Runbook에 반영하고, 실패 시 원복·재설계한다.

24.16 개선 과제 카드와 Go/No-Go

개선 과제 ID: OPS-EXAMPLE-024
문제: 외부망 UC 연결의 비정상 종료 증가
업무 영향: 사용자 재연결, 메시지 전달 지연
현재 기준선: 유효 연결 종료율 0.8% (가상)
목표: 동일 조건에서 0.3% 이하 (가상)
가설: 중간 Proxy Idle Timeout / Buffering 상호작용
변경: QA 재현 → 설정 비교 → 승인된 점진 적용
보안: WAF 정책·TLS·인증 경계 변경 여부 점검
확장성: 연결 수·FD·메모리·DB Pool 변화 검증
원복: 사전 승인 설정 Snapshot과 복귀 조건
완료 기준: 업무 SLI 개선 + 부작용 없음 + 증거 보존
승인: 업무 Owner / 운영 책임자 / 보안 담당
No-Go

계측 신뢰성이 없거나, 고객 업무 영향이 불명확하거나, 원복이 불가능한 변경은 성능 개선을 명분으로 운영에 적용하지 않는다.

통합 관측 플랫폼상관분석 용이중앙 장애·Vendor Lock-in버퍼·이중화·표준 포맷

규모가 커질수록 메트릭 Label의 고유 값 수, 로그 저장량, Trace 샘플링 비용이 증가한다. 사용자 ID·문서 번호를 메트릭 Label로 사용하지 않는다. 보안 이벤트와 업무 Trace의 접근 권한도 구분한다.

24.18 분기 종료 검수와 다음 장

  • 핵심 ERP·UC 업무별 SLI/SLO 정의서가 최신인가?
  • 월간 보고의 분모·측정 창·제외 규칙이 일관적인가?
  • 중요 사고에 PIR와 재발 방지 책임자가 지정되었는가?
  • 복구 훈련에서 RTO/RPO를 실제 측정했는가?
  • 개선 과제의 전후 데이터·부작용·비용이 검증되었는가?
  • 미해결 위험에 Owner·기한·승인 기록이 있는가?
  • 표준 구성·Runbook·CMDB가 변경 결과를 반영하는가?
  • 다음 분기 과제는 SLO 격차·보안·업무 영향에 따라 선정되었는가?
