공개 교육용 참조 설계

실제 고객·내부 시스템 정보 및 인증정보를 포함하지 않는다. 시험은 격리된 실습 환경에서 수행한다. 수치와 합격선은 예시이며 실제 지원 사양·계약·운영 정책이 우선한다.

28.1 시험 목표와 책임 경계

자동화 플랫폼의 성능 시험은 ERP·UC 자체의 TPS가 아니라 점검 수집, 정책 평가, 승인, 큐 처리, 실행 검증의 처리량과 지연을 평가한다. 시험 대상 자산에는 운영 시스템을 사용하지 않고 격리된 모의 SSH/API 대상과 테스트 네임스페이스를 사용한다.

28.2 부하 모델

자산 수 N, 자산당 점검 주기 T초, 점검당 이벤트 수 E라면 평균 유입률 λ=N×E/T (events/s)다. 예를 들어 1,200개 자산을 300초마다 2건씩 점검하면 8 events/s다. 피크 배수 5를 가정하면 40 events/s까지 평가한다. 숫자는 교육용 가정이며 실제 현장 측정값으로 교체한다.

28.3 대기열과 백프레셔

Little의 법칙 L=λW는 안정 상태의 평균 동시 작업 수를 설명한다. 예: 40 jobs/s, 평균 처리시간 0.5s라면 평균 동시 처리 20건이다. 이 식은 CPU 용량을 직접 산정하지 않으며 서비스 시간 분포·외부 API 제한·재시도를 별도로 고려한다. 큐 깊이 상한, 작업 TTL, 테넌트별 quota, 429/503 재시도 지수 백오프와 jitter를 시험한다.

28.4 시험 시나리오

Baseline(정상), Step(10→20→40 events/s), Spike(순간 5배), Soak(8시간), Queue backlog(Worker 50% 중지), Recovery(복구 후 큐 소진) 순서로 진행한다. 테스트 데이터는 가상 자산 ID만 사용하고 실제 운영 비밀키를 복제하지 않는다.

28.5 측정과 합격 기준

수집 성공률, 정책 평가 p95/p99, 큐 대기 p95, end-to-end 완료율, 메모리·CPU, 오류·재시도율, 테넌트 간 지연 격리를 관찰한다. 교육용 예시: 정상 부하에서 정책 p95 200ms 이하, 큐 대기 p95 5초 이하, 완료율 99.9% 이상. 실제 합격선은 SLO·측정 환경과 계약 기준으로 결정한다.

28.6 재현 가능한 결과 기록

시험 코드 버전, 인프라 BOM, 워커 수, 큐 설정, 샘플 크기, 관측 기간, 시작/종료 시각, p50/p95/p99, 실패 유형과 재실행 조건을 저장한다. 평균만 보고 합격 처리하지 않으며 warm-up, 시계 동기화, 부하 발생기 병목을 확인한다.
