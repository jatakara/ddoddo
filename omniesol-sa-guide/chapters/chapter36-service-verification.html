공식 제품 지원 사양이나 성능 보증이 아니다. 실제 적용은 공식 문서, 계약 및 승인된 변경 정책을 우선한다.

36.1 설치 완료와 운영 가능 상태의 차이

설치 프로그램의 종료 코드 0은 명령이 정상 종료됐다는 뜻이지 업무가 정상이라는 뜻은 아니다. 프로세스 기동, 포트 연결, 애플리케이션 준비 상태, 업무 트랜잭션, 복구 가능성을 순서대로 검증한다. Day-0은 설계, Day-1은 구축, Day-2는 운영과 지속 개선을 의미한다.

36.2 Linux 및 네트워크 기준 상태

설치 직후 기준 상태를 남겨 이후 장애 분석의 비교 대상으로 삼는다. 다음 명령은 읽기 전용 예시이며 승인된 계정에서 실행한다. 출력에는 내부 주소와 서비스명이 포함될 수 있으므로 공개 저장소에 올리지 않는다.

systemctl --failed
free -h
lsblk -f
df -hT
df -i
ss -lnt
ip route
chronyc tracking

실패한 unit이 없더라도 필수 서비스가 누락될 수 있다. 승인된 서비스 목록과 실제 상태를 비교하고, DNS와 TLS는 실제 사용자 접속 경로에서 검증한다. 디스크 여유는 로그 및 데이터 증가율과 함께 평가한다.

36.3 ERP WEB/WAS/Oracle 검증

계층검증판정 증거
WEB정상 DNS 및 TLS, 승인된 URLHTTP 상태·인증서 체인
WAS배포 상태, JDBC 연결, 오류 로그업무 요청 성공·응답시간
OracleDB/PDB 상태, 접속 서비스, 읽기 검증DBA 확인 결과
-- 승인된 DBA 계정, 해당 DB에서 실행
SELECT name, open_mode, database_role FROM v$database;
SELECT name, open_mode FROM v$pdbs;

PDB 조회는 멀티테넌트 구성에서 적용한다. 실제 업무용 서비스명으로 접속해야 하며 DB OPEN만으로 애플리케이션 접속을 보증할 수 없다. 운영 DB에 임의 DML을 실행하지 않는다.

36.4 UC Kubernetes 검증

kubectl get nodes
kubectl get deployments,statefulsets,pods -n <namespace>
kubectl get svc,endpointslices,pvc -n <namespace>
kubectl get events -n <namespace> --sort-by=.metadata.creationTimestamp

Running과 Ready는 다르다. Deployment의 available replica, Service의 EndpointSlice, PVC Bound 여부를 함께 확인한다. PVC Bound는 실제 쓰기 성공을 보장하지 않는다. Ingress를 거친 외부 접속과 내부 서비스 연결을 별도로 시험한다. 권한은 대상 namespace 읽기 범위로 제한한다.

36.5 업무 시나리오 검수 Matrix

업무시험 방법통과 기준
ERP 로그인·조회승인된 테스트 계정권한에 맞는 조회 성공
ERP 저장격리된 시험 회사 또는 QA저장·재조회 정합성
UC 메시지·파일시험 사용자 간 전송수신·다운로드 확인
연계·배치시험 데이터 및 승인된 대상중복 없이 완료

실제 결재·메일·회계 전표가 외부로 전송되지 않도록 시험 범위를 격리한다. 기능 미도입은 N/A, 증거 부족은 UNKNOWN으로 구분한다.

36.6 성능 기준선과 인수 판정

동일 업무·동일 부하·동일 측정 구간에서 응답시간 p95, 오류율, CPU, 메모리, DB 대기 및 스토리지 지연을 기록한다. 예를 들어 1000건 중 995건 성공은 99.5%이며 p95 1.8초라는 수치만으로 월간 SLA를 보장하지 않는다. 정상 및 장애 시 용량은 7장과 16장의 기준으로 별도 검증한다.

필수 업무 실패, 데이터 정합성 오류, 인증 우회는 운영 전환 차단 조건이다. 시험 시각, 버전, 대상, 담당자, 증거 위치를 검수서에 남긴다.
