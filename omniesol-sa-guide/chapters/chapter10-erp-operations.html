10장 3부. ERP 운영·검증

10.9~10.12 · 운영 경계, 관측성, 장애 진단, 인수인계

10.9 운영·보안 경계

ERP 단독형은 업무와 운영 책임을 명확히 분리해야 한다. 사용자 요청, WEB/WAS 처리, DB 접근, 관리 작업의 경계를 구성도에 표시하고 변경 승인 체계를 정의한다.

항목설계 판단
접속 경로사용자와 시스템 간 통신 구간, TLS 종료 위치 확인
접근 권한업무·운영 계정의 역할과 승인 절차 분리
패치 관리지원 버전, 유지보수 일정, 사전 시험과 롤백 계획
확장성WAS 증설 시 연결 풀과 DB 처리량 한계를 함께 검토

10.10 관측성: 사용자 체감에서 원인 계층까지

CPU 평균값 하나로 정상 여부를 판단하지 않는다. 사용자 요청을 계층별로 나누고 같은 시간대의 지표를 비교한다.

계층관측 지표확인할 가설
브라우저TTFB, 정적 리소스 전송, 렌더링 시간전송 지연 또는 프런트엔드 실행
WEB응답코드, 업스트림 지연, 요청 큐연결·라우팅 병목
WASp95, 스레드 대기, 연결 풀, GC동시성·업무 로직 병목
DBSQL 지연, 잠금, I/O 대기쿼리·트랜잭션 경합
호스트메모리, CPU 대기, 스토리지 지연기반 자원 부족

계층 간 시계가 다르면 장애 시점 비교가 어렵다. 시간 동기화와 요청 단위 추적 체계를 마련한다.

10.11 현장 장애 분석 예제

가상 사례: 월말 마감 시간에 ERP 조회가 느려졌지만 WAS CPU는 35%다. CPU가 낮다고 문제가 없다고 판단하지 않는다.

순서진단 방법
1특정 메뉴·사용자·시간대인지 영향 범위 구분
2브라우저·WEB·WAS·DB 지연을 단계별 분리
3WAS 대기 큐, DB 연결 풀, DB 잠금 비교
4변경 전후 p95·오류율·처리량으로 효과 검증

DB 잠금이나 연결 풀 대기로 작업이 기다리면 CPU 사용률이 낮아도 사용자 응답시간은 길어질 수 있다.

10.12 운영 인수인계 체크리스트

점검완료 기준
□ 구성공식 지원 조합, 구성도, 장애 영역 확정
□ 용량피크 성능과 장애 시 잔여 처리량 검증
□ 복구백업·복원 시험과 RPO/RTO 합의
□ 운영경보·로그·변경 승인·롤백 절차 인계
□ 보안권한 검토, 변경 이력, 정보 공개 범위 승인

본 장은 공개 교육용 참조 아키텍처이며 공식 제품 사양을 대체하지 않는다.
