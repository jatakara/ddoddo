공개 교육용 참조 설계

공식 제품 설치 사양이 아니다. 모든 수치와 경로는 교육용 예시이며 실제 적용은 지원 버전, 계약, 변경 승인 및 보안 정책을 우선한다.

33.13 자동 검증 참조 구조

승인된 환경 입력 + 버전별 Baseline
              ↓
       Read-only Collector
              ↓
       정규화 및 Policy 평가
              ↓
       Evidence / Readiness Report
              ↓
          Go / No-Go 승인
              ↓
       별도 Installation Runner
              ↓
       사후 검증 및 인수인계

수집기와 설치 실행기를 분리하고 SSH 호스트키 검증, 단기 권한, 대상 allowlist를 적용한다. GUI는 실행 상태를 보여주는 인터페이스이며 권한 통제는 서버 측에서 수행한다.

33.14 기계 판독형 검사 계약

profile: example-erp
baseline_version: training-v1
checks:
  - id: memory.minimum
    critical: true
    unit: GiB
    expected_min: 64
  - id: dns.service
    critical: true
    expected: resolvable

64 GiB는 교육용 값이다. 정책 입력은 스키마 검증을 거치며 임계값·대상·수집 시간·단위·근거를 기록한다. 명령 문자열을 사용자 입력에서 직접 조합하지 않고 승인된 검사 ID에 매핑한다. 검사별 제한시간과 결과 크기 상한을 설정한다.

33.15 판정 규칙과 증거

상태의미처리
PASS기준 충족 및 증거 유효통과
FAIL기준 불충족해소 후 재검사
UNKNOWN접근 실패·증거 부족·만료재검사 또는 담당자 이관
NOT_APPLICABLE프로파일상 불필요적용 제외 근거 저장

필수 검사의 FAIL·UNKNOWN은 No-Go다. 예외는 책임자·만료일·보완통제를 명시하며 제품 필수 요구조건을 우회하는 수단으로 사용하지 않는다. 결과 파일은 민감정보를 제거하고 접근통제된 저장소에 보관한다.

33.16 현장 실습: 설치 보류 판단

검사교육용 결과판정
메모리64 GiB / 기준 64 GiBPASS
DB 데이터 영역350 GiB / 기준 500 GiBFAIL
DNS승인 FQDN 해석PASS
NTP수집 시간 초과UNKNOWN
K8s API비 Kubernetes 프로파일NOT_APPLICABLE

결론은 No-Go다. 구축 담당자가 저장소를 확장하고 NTP 수집 실패 원인을 해결한 뒤 전체 관련 검사를 재실행한다. GUI에서 성공률이 높게 표시되더라도 필수 검사 실패를 상쇄할 수 없다.

33.17 설치 실행 승인과 재검증

승인은 대상 호스트 식별자, 프로파일·Baseline 버전, 설치 아티팩트 digest, 보고서 digest, 유효기간에 바인딩한다. 실행 직전에 상태가 달라졌는지 재검증하고 승인 범위 밖 변경을 차단한다. 단계별 체크포인트와 중복 실행 방지 키를 사용한다. 시간 초과 뒤 상태가 불명확하면 자동 재실행 전에 실제 상태를 확인한다.

Zero-Touch는 무승인 실행을 뜻하지 않는다. 사전 승인된 정책 내 반복 작업을 자동 수행하고, 불확실하거나 비가역적인 작업은 사람에게 이관한다.

33.18 운영 수용 체크리스트와 비용 판단

  • 배포 프로파일과 지원 Matrix가 일치한다.
  • 필수 검사에 FAIL·UNKNOWN이 없고 증거 유효기간이 남아 있다.
  • 네트워크 경로, 인증정보, 아티팩트 출처 및 권한을 검증했다.
  • 실패 시 재개·원복·담당자 이관 절차를 시험했다.
  • 실제 설치 후 업무 기능 검수와 운영 인수인계를 별도 수행한다.

가상 예시: 월 20건, 수동 점검 3시간 대비 자동화 후 검토 0.75시간이면 45시간 절감이다. 시간 단가 5만원이면 월 225만원의 총 노동시간 가치가 발생한다. 플랫폼 운영비 월 100만원을 차감한 순효과는 125만원이며 초기 개발비·오탐 대응은 별도 산정한다. 다음 장은 설치 실행 오케스트레이션과 실패 복구를 다룬다.

참조: Red Hat 문서 · Oracle Database 문서 · Kubernetes 문서. 적용 버전의 공식 요구사항을 확인한다.
