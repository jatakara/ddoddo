공개 기술서 이용 안내

독립 교육용 초안으로서 제조사의 공식 설치·지원 매뉴얼이 아니다. 실제 구축에서는 계약된 제품 범위, 공식 호환 버전, 고객 보안 정책과 승인된 변경절차를 우선한다.

2.1 System Landscape의 의미

Landscape는 설치된 서버의 목록이 아니다. 업무 서비스, 구성요소, 데이터, 네트워크 경계, 설치 환경, 운영 책임의 관계를 나타내는 시스템 지도다. 같은 ERP라도 사용 규모, 고객 보안 정책, IDC 배치, SaaS/온프레미스 조건에 따라 실제 구조가 달라진다.

백업과 DR은 개발 → 운영 다음에 자동 수행되는 단계가 아니라, 운영 데이터의 복구 가능성을 검증하는 별도 체계다.

2.2 DEV·QA·PROD 환경 분리

환경목표분리할 항목검증
DEV기능 구현, 반복 변경계정, 데이터, 인증서, 외부 연계운영 데이터 접근 불가
QA/STAGE통합 테스트, 릴리스 승인배포 경로, 테스트 자료운영과 설정 차이 기록
PROD실업무 처리, 안정성 유지변경 권한, 백업, 로그 보존업무/복구 목표 충족
DR중단 후 복구데이터 복제, 시설·접속 경로복구 소요 시간 측정

URL만 다르고 동일한 DB를 공유한다면 데이터 분리라고 볼 수 없다. 특히 사용자 계정, API 토큰, 메일 발송 계정, 외부 기관 연계 등은 DEV에서 운영으로 잘못 호출되지 않도록 통제한다.

보안 실무

운영 데이터의 테스트 환경 복제는 마스킹/비식별화, 접근 권한, 보존 기간 검토 후 승인 절차를 거쳐야 한다.

2.3 인프라 구성요소 인벤토리 만들기

고객에게 “서버 정보를 주세요”라고 요청하는 것만으로는 구조를 알 수 없다. 역할, 소유자, 통신 관계, 데이터 분류, 운영 책임을 한 번에 정리해야 한다.

속성기입 예시(가상)필요 이유
시스템 역할ERP WEB / ERP WAS / ERP DB / UC Gateway점검 책임 할당
배포 형태물리 / VM / Container장애 공유 경계 파악
의존성WAS → DB, UC → IdP단일 실패 영향 평가
접속사용자 → FQDN → Proxy외부/내부 경로 일치
데이터DB 파일 / 첨부 / 세션복구 및 보존 전략
운영 소유자고객사 / 구축사 / 제조사장애 에스컬레이션

공개 기술 문서에는 실제 고객 IP나 내부 FQDN, 계정명, 라이선스 키를 싣지 않는다. 예시는 RFC 문서용 도메인인 example.invalid와 비식별 가상값을 사용한다.

2.4 Logical과 Physical 구성도 구분

논리도는 “누가 누구를 호출하는가”를 설명하고 물리도는 “어디에서 실행되는가”를 설명한다. 두 장을 혼합하면 K8s의 Namespace는 분리되어 있는데 물리 노드·디스크는 공유한다는 사실을 놓치기 쉽다.

도면필수 표시검토 목적
논리 아키텍처브라우저, 업무 서비스, 데이터, 호출 방향업무 흐름, 접근 통제
물리 아키텍처VM/호스트/스토리지/LB/네트워크HA와 공통 장애 도메인
트래픽 흐름도FQDN, 프로토콜, 출발지/목적지방화벽·TLS·Proxy 검증
운영 의존성도DNS, NTP, 인증, 백업, 모니터링숨은 단일 장애점 탐색

ERP와 UC를 다른 서버에 배치해도 동일 스토리지 어레이나 Load Balancer를 사용하면 물리적 공통 실패가 존재할 수 있다.

2.5 가용성·복구 목표 이해

지표뜻확인 방법
HA일부 컴포넌트 장애에도 서비스가 유지되는 특성노드/인스턴스 장애 주입 시험
RTO중단 이후 허용 가능한 업무 복구시간실제 복구 훈련 시간
RPO허용 가능한 데이터 손실의 시점 차이백업·로그 적용 후 데이터 확인
DR주 센터의 중대한 장애에서 다른 경로로 복구네트워크·인증·데이터 포함 전체 시험

RTO와 RPO는 제품 기능으로 임의 결정할 수 없다. 고객의 업무 우선순위와 중단 비용을 기준으로 협의하고 그 목표에 부합하는 백업 방식과 이중화 비용을 검토한다.

실무 판단

HA 구성에도 소프트웨어 논리 오류나 잘못된 데이터 삭제는 전파될 수 있다. HA와 백업/복구는 상호 대체 관계가 아니다.

2.6 Landscape 리뷰 체크리스트

  • DEV/QA/PROD가 DB·비밀정보·외부 연계를 독립적으로 관리하는가?
  • ERP 단독·UC 단독·공동 서비스를 모두 표기했는가?
  • 공통 DNS, SSO, 스토리지, 하이퍼바이저, LB 장애를 검토했는가?
  • RTO/RPO와 복구 책임자·연습 주기를 문서화했는가?
  • 논리도와 물리도의 서비스 및 자원 수량이 일치하는가?
  • 변경·배포·원복 경로와 접근제어를 검토했는가?
