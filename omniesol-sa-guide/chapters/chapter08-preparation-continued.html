8장. 설치 전 인프라 준비 (후반)

8.7~8.11: DB·스토리지·백업, Kubernetes, 검증 증거, 설치 승인과 체크리스트

8.7 DB·스토리지·백업·복구

DB 프로세스가 실행된다고 설치 준비가 끝난 것은 아니다. 데이터·로그·임시 영역의 성능과 복구 가능성까지 확인한다.

영역확인할 질문증거
호환성DB 엔진·버전·패치가 공식 지원 조합인가?공급사 검증 매트릭스
저장공간초기 크기, 증가율, 보존 기간, 임시 공간을 계산했는가?용량 계획서
성능업무 피크의 IOPS, 처리량, 지연을 검증했는가?성능 시험 결과
백업정합성·보존·암호화·오프사이트 보관 정책이 있는가?백업 정책과 로그
복구복원 시험으로 RPO/RTO 충족을 확인했는가?복구 시험 기록
RPO는 허용 데이터 손실 시점의 목표, RTO는 복구 완료까지 허용되는 시간 목표다. 백업 성공과 복구 성공은 다르다.

8.8 Kubernetes 기반 UC 사전점검

실제 UC 배포 모델이 Kubernetes일 때 추가로 확인한다. 공식 제품별 요구사항을 우선한다.

항목확인 내용
노드·가용성장애 영역, Worker 자원, 노드 1대 장애 시 잔여 수용량
스케줄링Pod requests/limits, 배치 정책, 유지보수 중 가용성
영속 데이터PVC, StorageClass, 접근 모드, 복원 절차
네트워크Service, Ingress, 내부 DNS, 외부 연계
보안RBAC, Secret 보호, 이미지 검증, 네트워크 분리
운영지표·로그·경보, 버전 호환성, 업그레이드·롤백

노드의 물리 RAM 전체를 Pod에 할당할 수 없다. OS·시스템 예약, DaemonSet, 장애 여유를 제외해 계산한다.

8.9 점검 결과는 증거로 남긴다

OS 버전, 시간 동기화, 파일시스템 여유, DNS 응답, TLS 체인, 서비스 연결, 클러스터 상태를 읽기 전용 방법으로 확인한다. 결과는 시각·담당자·판정 기준과 함께 기록한다.

공개 GitHub에는 실제 IP, 내부 호스트명, 인증정보, 운영 로그 원본, 비공개 구성도와 고객 식별 정보를 올리지 않는다.

8.10 설치 승인 게이트

판정기준조치
Go지원 사양, 연결성, 보안, 복구, 담당자와 시험 계획이 검증됨설치 승인
Conditional Go경미한 잔여 이슈에 임시 통제·기한·책임자 합의조건부 승인 기록
No-Go지원 미확인, 필수 연결 실패, 복구 불가, 보안 승인 부재설치 보류 후 재점검

데이터 손실·보안 사고·핵심 업무 중단으로 이어질 수 있는 이슈는 단순한 조건부 승인으로 넘기지 않는다.

8.11 현장용 사전점검 체크리스트

항목완료 기준
□ 범위와 R&R서비스 범위, 담당자, 에스컬레이션 확정
□ 공식 호환성OS·DB·WAS·클러스터 검증 조합 확인
□ 용량과 장애 여유CPU·RAM·디스크·N+1 가정 검토
□ 네트워크·인증서DNS·시간·TLS·최소 허용 경로 시험
□ 백업·복구복원 시험 계획, RPO/RTO, 책임자 확정
□ 관측성과 변경관리모니터링, 변경 승인, 원복 기준 확보
