공개 교육용 참조 설계

계약·SOW·제품 공식 지원 문서가 우선한다. 고객 정보·비공개 정책·실제 자격증명은 포함하지 않는다.

참조 책임 아키텍처

고객(서비스 Owner / 승인권자)
   ├─ 인프라 구축사 → 서버·스토리지·네트워크·보안 준비
   │                    ↓ 환경조사서 + 시험 증거
   └─ 패키지 공급사 → 지원 사양·설치 요구·적합성 검토
                        ↓ 공동 Go/No-Go
                  설치 → SAT → 운영 인수

운영 판단: 패키지 지원 요건을 제시하는 것과 고객 인프라를 대신 설계·운영하는 것은 별개다. 확장성·보안·복구 가능성을 설치 전 함께 검증한다.

30.7 환경조사서의 소유권

환경조사서의 실제 구성값은 환경을 소유·구축하는 주체가 작성한다. 패키지 공급사는 필수 항목 정의, 제품 호환성 확인, 검토 의견을 담당한다. 대리 작성은 별도 합의와 근거 자료가 필요하다.

30.8 필수 입력 Matrix

자산 ID, 역할, OS 버전, CPU/RAM, 디스크 성능·용량, IP/DNS, VIP/LB, 방화벽 출발지·목적지·포트·방향, TLS 인증서, 계정, 백업, RTO/RPO, 유지보수 창을 수집한다. 제품별 포트·사양은 승인된 공식 지원 문서에서만 확정한다.

30.9 증거 기반 Readiness

PASS는 명령 출력·설정 화면·테스트 시각·승인자 등 재현 가능한 증거가 있어야 한다. FAIL은 기준 위반, UNKNOWN은 증거 부족이다. UNKNOWN을 PASS로 간주하지 않는다.

30.10 방화벽·연계 검증

통신 경로는 Source → Destination → Protocol/Port → Purpose → Owner → Test Evidence로 관리한다. 단순 TCP 연결 성공은 TLS 협상·애플리케이션 인증·업무 정상성을 보증하지 않는다.

30.11 보안과 확장성

최소 권한, 계정 수명, 암호화, 감사로그, 관리망 분리, 저장소 암호화와 백업 복원 검증을 확인한다. 확장 계획에는 CPU/RAM뿐 아니라 DB IOPS, 네트워크 대역폭, 노드 장애 시 여유 용량과 라이선스 영향을 포함한다.

30.12 설치 Go/No-Go

차단 항목(지원 불가 버전, 핵심 포트 미연결, 관리자 권한 부재, 미승인 보안 예외, 복구 수단 부재)은 No-Go다. 비차단 미결사항은 책임자·기한·보완 통제·승인 기록이 있을 때만 조건부 진행한다.
