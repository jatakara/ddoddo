25.13 복구 훈련 계획서

복구 훈련은 백업 파일을 확인하는 행위가 아니라 정의된 시점의 데이터를 실제로 복원해 업무를 검증하는 활동이다. DB·파일·메시지 저장소가 서로 다른 시점으로 복원되면 정합성이 깨질 수 있다. RTO와 RPO는 고객이 승인한 업무 목표이며 도구의 기본값이 아니다.

Recovery Exercise ID: DR-EXAMPLE-025
서비스: ERP 전표 저장 / UC 첨부파일 (가상)
환경: 독립 격리된 복구 시험 환경
시나리오: DB 손상 / 파일 저장소 손실 / 노드 장애
목표 RTO: 업무 Owner 승인값
목표 RPO: 업무 Owner 승인값
복구 기준 시점: <timestamp>
대상 데이터: DB + 파일 + 연계 메타데이터
사전 조건: 백업 체인·키·권한·스토리지·DNS
실행 책임: DBA / 인프라 / 업무 검증자
데이터 보호: 운영망·외부 연계 차단, 마스킹
성공 조건: DB 정합성 + 로그인·조회·저장·첨부
중단 조건: 운영 영향 / 데이터 유출 위험 / 시간 초과
증거: 작업 로그, 체크섬, 복구 시각, 업무 테스트
승인/사후 조치: <role>
현장 적용 판단

복구 훈련에 운영 원본 DB나 실제 고객 개인정보를 무단 사용하지 않는다. 격리 환경과 승인된 데이터 복제·마스킹 절차가 선행되어야 한다.

25.14 RTO/RPO 측정과 복구 결과서

RTO는 장애로 업무가 중단된 시점부터 합의한 업무 기능이 복구될 때까지의 시간으로 측정한다. RPO는 복구 시점과 복구된 데이터의 최신 유효 시점 사이의 차이다. 훈련 결과에서는 데이터 파일 복원 완료와 업무 복구 완료를 구분한다.

측정 항목가상 결과판정
장애 시각09:00시작 기준
DB 복원 완료10:05업무 복구 아님
ERP·UC 기능 정상10:40업무 복구 시각
실측 RTO100분목표 120분 이내 → PASS
복구 데이터 최신 시각08:50RPO 10분
목표 RPO15분PASS
첨부/메타데이터 정합성일치 검증PASS

위 시간과 목표는 계산 방법을 설명하는 가상 예시다. 실제 서비스의 복구 판정에는 인증, 외부 접근, 배치 재개, 메시지 재전송·중복 제거와 사용자 업무 확인을 포함한다.

25.15 운영 인수인계 패키지

구축팀이 설치 완료를 선언했더라도 운영팀이 장애를 감지·복구할 수 없다면 운영 전환은 끝나지 않았다. 인수인계는 문서 전달과 실제 수행 능력 검증을 함께 진행한다.

인계 항목필수 내용수용 시험
아키텍처논리/물리도, 서비스 의존성요청 경로 설명 가능
인벤토리/CMDB호스트·역할·버전·담당현행 구성과 대조
계정·접근권한 승인, 비밀 관리 위치최소 권한 로그인 확인
모니터링SLO·알람·연락 경로테스트 경보 전달
백업/DR백업 정책·복구 Runbook복원 시험 수행
변경/배포Manifest·승인·원복STAGE 배포·원복 리허설
보안인증서·방화벽·취약점 이력만료·권한 점검
지원/RACI담당자·지원 범위·에스컬레이션모의 사고 연락 훈련
현장 적용 판단

비밀번호와 개인키는 인수인계 PDF에 첨부하지 않는다. 권한 위임은 비밀 관리 체계에서 승인·회수 가능하도록 구성한다.

25.16 현장 실습 A: ERP 저장 장애

실습 조건은 모두 가상이다. ERP 로그인과 조회는 정상이나 전표 저장이 실패한다. DB 서버 CPU는 낮고 WAS 연결 풀 대기 시간이 증가한다. 목표는 서버 재기동 없이 영향 범위를 파악하고 증거 기반으로 가설을 좁히는 것이다.

단계수행 과제제출 증거
1유효 저장 요청 실패율과 최초 시각 확인업무 SLI 스냅샷
2WAS Thread/DB Pool/Timeout 관측관측 시각·설정 버전
3DB Session/Lock/Wait 분석민감정보 제거된 대기 지표
4최근 변경과 배치 작업 비교Change ID·작업 ID
5복구/원복 판단과 업무 검증승인·전표 저장 결과
6PIR 및 재발방지 과제 작성Owner·Due date·측정 기준

합격 기준은 임의 재기동이 아니라 사실·가설·검증·승인·복구 결과가 분리된 장애 기록을 완성하는 것이다.

25.17 현장 실습 B: UC 외부 접속과 복구

UC 내부망 연결은 정상이나 외부망의 실시간 연결이 반복 종료된다. DNS·TLS·WAF·L7·Proxy·Ingress·Pod 순으로 경로를 비교하고, 정상 HTTP 200 이후 스트림 종료가 발생하는지 확인한다.

관찰 지점수집할 증거주의
브라우저연결 시작/종료·요청 ID토큰/개인정보 제거
DNS/TLS해석 결과·인증서·SNI실제 FQDN은 비공개
WAF/L7정책 히트·Idle Timeout보안 우회 금지
Proxy/Ingress업스트림 응답·버퍼링·타임아웃설정 변경은 승인 필요
Pod/서비스Ready·재시작·연결 수Pod Running만으로 판정 금지
업무 검증재연결·메시지 중복/누락실제 사용자 경험 확인

확장성 검토에서는 장시간 연결 증가에 따른 FD, 메모리, LB 세션 수를 확인한다. 보안 검토에서는 인증 우회·과도한 Rewrite 예외가 없는지 점검한다.

평가 영역배점(교육용)합격 증거

합계10080점 이상 + 중대 보안 위반 없음

점수는 학습 평가를 위한 가상 기준이다. 실제 운영 수용은 고객 승인과 계약상 검수 기준을 따른다. 산출물의 품질은 작성된 표의 개수가 아니라 운영자가 장애를 안전하게 분석하고 복구할 수 있는지로 평가한다.

  • 원본 운영 데이터를 교육용 저장소에 복사하지 않는다.
  • 업무 성공 여부를 테스트 ID로 재현할 수 있다.
  • 운영팀이 변경·복구 Runbook을 직접 수행해 본다.
  • 미해결 위험은 수용 승인·담당·기한을 남긴다.
