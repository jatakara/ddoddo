공개 교육용 참조 설계

고객 식별자·내부 주소·비밀정보를 포함하지 않는다. 실제 적용은 제품 지원 사양, 보안 정책 및 변경 승인에 따른다. 수치와 SLO는 교육용 가정이다.

27.7 테넌트와 환경의 경계

고객·조직·DEV/QA/PROD별로 자산 범위, 정책, 자격증명, 작업 큐, 증거 저장소 접근 권한을 구분한다. UI에서 보이지 않는 것만으로 격리가 성립하지 않는다. API 객체 수준 인가와 저장소 쿼리 필터를 함께 검증한다.

Runner 서비스최소불가불가서명·만료된 승인 범위만

SSO/MFA, RBAC와 자산·환경 속성 기반 ABAC를 조합한다. 승인자와 요청자 분리, 운영환경 추가 승인, 긴급 변경의 사후 검토를 적용한다.

27.9 단기 자격증명과 비밀 관리

SSH 개인키, DB 암호, API 토큰을 작업 YAML·로그·Git에 기록하지 않는다. Secret Manager 또는 Vault에서 대상·명령·시간창에 제한된 단기 자격증명을 발급하고 만료·회수한다. 에이전트와 서버는 상호 TLS 인증, 인증서 갱신·폐기 절차를 갖춘다.

27.10 정책 무결성과 공급망

정책·Runbook은 Git에서 코드 리뷰와 서명된 릴리스로 관리한다. 실행 시 정책 버전, Artifact SHA-256, 승인 ID를 결속한다. 의존성·컨테이너 이미지 스캔, SBOM, 최소 권한 이미지, 패치 SLA를 운영한다. 서명 검증 실패 시 실행을 거부한다.

27.11 감사 로그의 증거성

누가 언제 어떤 자산에 어떤 정책 버전으로 승인·실행·검증했는지 상관 ID로 연결한다. 로그는 민감정보 마스킹, 시간 동기화, 접근 통제, 보존·파기 정책과 변경 탐지 기능을 갖춘다. Append-only나 WORM 저장소도 관리자 권한과 보존 정책을 별도로 점검해야 한다.
