공개 교육용 참조 설계

실제 고객·내부 시스템 정보, 인증정보, 비공개 구성은 포함하지 않는다. 모든 공격·복구 실습은 격리된 환경에서 수행한다. 실제 지원 버전·계약·보안 정책이 우선한다.

참조 아키텍처

Developer → Reviewed PR → CI (SAST/SCA/Secret Scan)
         → Isolated Build → SBOM + Provenance + Signature
         → Artifact Registry → Admission Policy
Operator (SSO/MFA) → Controller → Policy Engine
                                 ↓ Approved job (TTL, hash)
                         Isolated Action Runner → ERP/UC/DB
                                 ↓
                          Immutable Audit Evidence

확장성: 테넌트별 큐와 Runner 동시성 한도를 두고 중앙 Policy Engine·Audit Store의 병목을 측정한다. 보안: 신원·승인·실행·감사 경계를 분리하고 변경 권한은 기본 거부한다.

29.13 취약점 우선순위

CVSS 점수는 기술적 심각도 지표이지 운영 위험의 완전한 척도가 아니다. 인터넷 노출, 권한 수준, 실제 악용 징후, 영향 자산, 보완 통제, 수정 가능성을 함께 평가한다. 긴급 패치에도 사전 백업·호환성 시험·롤백 계획이 필요하다.

29.14 보안 검증 Matrix

신원: MFA·서비스 계정 최소권한 / 공급망: SBOM·서명 검증 / 정책: 변경 승인 무결성 / Runner: 명령 allowlist·격리 / 감사: 누락·변조 탐지 / 복구: 토큰 회전·정책 롤백 / 확장: 테넌트 간 자원·권한 격리. 각 항목에 PASS·FAIL·UNKNOWN 및 증거 링크를 부여한다.

29.15 보안 사고 대응 Runbook

의심 징후 탐지 → 변경 실행 일시 중지 → 증거 보존 → 영향 범위 파악 → 자격증명 폐기·회전 → 격리 환경 검증 → 단계적 복구 → 사후 분석. 로그 삭제나 무조건적 서버 재시작은 증거를 훼손할 수 있으므로 우선하지 않는다.

29.16 지표와 목표

정책 우회 0건, 승인 없는 변경 0건은 절대적인 수용 기준이다. 패치 리드타임, 만료된 예외 건수, 미검증 배포 비율, 비밀정보 회전 성공률, 보안 사고 탐지·차단 시간은 추세로 평가한다. 검출률 상승이 실제 위험 증가인지 관측 개선인지 구분한다.

29.17 개선 비용과 Trade-off

격리 Runner는 보안 경계를 강화하지만 구축·유지 비용이 증가한다. 전면 차단형 정책은 안전하지만 가용성에 영향을 준다. 고위험 운영 변경은 fail-closed, 읽기 전용 진단은 제한적 degrade 모드로 분리한다. 개선 우선순위는 예상 손실 감소와 검증 비용으로 결정한다.

29.18 Go/No-Go 및 다음 단계

미승인 변경, 교차 테넌트 실행, 서명 미검증 배포, 감사 무결성 실패는 즉시 No-Go다. 조건부 예외는 범위·책임자·보완 통제·만료일을 기록한다. 다음 장에서는 고객 자체 구축 환경에서 적용할 수 있는 책임 경계와 지원 운영 모델을 다룬다.

현장 점검 및 참고 표준

검증은 요청 ID, 정책 버전, 아티팩트 digest, 승인자, 대상 ID, 결과 로그로 추적한다. 기준 자료: SLSA v1.0, NIST SSDF SP 800-218, OWASP Top 10, Kubernetes Security. 제품별 지원 여부는 별도 검증한다.
