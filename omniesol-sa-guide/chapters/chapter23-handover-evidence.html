23.7 인수인계 패키지의 범위

운영 인수인계는 서버 목록과 관리자 계정을 전달하는 행위가 아니다. 운영팀이 원래 구축자 없이도 상태를 판단하고 승인된 복구를 수행할 수 있는 최소한의 지식과 증거를 전달하는 과정이다.

인계 산출물필수 내용검수 포인트
논리/물리 구성도접속·데이터·장애 도메인·Owner현행 배포와 일치
BOM·CMDB제품·OS·DB·WAS·K8s·라이선스버전·지원 종료 확인
네트워크 정책표FQDN·VIP·Port·TLS 종료 위치실제 경로와 일치
운영 Runbook기동·중지·로그·모니터링·원복운영팀 실습 통과
백업·복구 문서RPO/RTO·백업·복원·DR실제 복구 증거

23.8 증거의 품질과 보관

검수 증거는 나중에 동일한 조건으로 결과를 재현할 수 있어야 한다. 단순 스크린샷 한 장보다 시험 ID, 요청 시각, 버전, 환경, 예상 결과, 실제 결과, 로그 링크를 포함한 구조화된 기록이 유용하다.

TEST-ID: SAT-ERP-LOGIN-001
ENV: STAGE-2026Q4 (가상)
BUILD: release-2026.11.x
START/END: ISO-8601 timestamp
PRECONDITION: approved test user, sample dataset
EXPECTED: login and menu access succeed
ACTUAL: PASS
EVIDENCE: protected artifact store / SAT-ERP-LOGIN-001
ISSUE: none
REVIEWER: service owner (role only)
개인정보 보호

증거에 실명·계정 비밀번호·토큰·쿠키·주민번호·고객 내부 IP를 포함하지 않는다. 로그는 접근 제한된 저장소에 보관하고 보존 기간과 파기 책임을 정의한다.

23.9 RACI와 장애 에스컬레이션

RACI는 Responsible(실행), Accountable(최종 책임), Consulted(협의), Informed(통보)로 구성한다. 각 활동에는 최종 책임자 A를 명확히 지정하고, 공급사 지원 범위와 고객 운영 권한을 구분한다.

활동R(실행)A(최종 책임)C/I
서비스 모니터링운영팀서비스 Owner업무·SA
DB 복구DBA운영 책임자업무·보안
방화벽 변경네트워크/보안변경 승인권자SA·운영
제품 패치제품 기술 담당변경 승인권자운영·DBA
업무 수용업무 테스트 담당업무 책임자SA·운영
DR 전환DR 운영팀위기관리 책임자DBA·업무

역할은 조직마다 다르므로 이 표는 예시다. 운영 인계 전에 실제 조직명과 연락 채널을 별도 접근 제한 문서로 관리한다.

23.10 Runbook 실습과 Knowledge Transfer

문서만 전달하고 서명을 받는 것은 충분하지 않다. 인수자가 직접 알람을 식별하고 장애 원인 범위를 좁히며, 안전한 조치와 롤백을 설명할 수 있어야 한다.

  • 실습 대상은 DNS/TLS/Proxy, WAS/DB 연결, K8s Pod/Service, 백업 실패 알람을 포함한다.
  • 관찰 명령과 변경 명령을 분리하고 운영팀의 권한을 사전에 점검한다.
  • 복구가 필요한 시험은 격리된 검증 환경에서 수행한다.
  • 실습 후 Runbook의 실제 수행시간과 누락된 전제조건을 수정한다.

23.11 미해결 이슈·예외·기술 부채 인계

모든 경미한 결함을 해결할 때까지 운영 전환을 무한정 미룰 수는 없다. 반대로 심각한 보안 취약점이나 복구 불능 상태를 “추후 조치”로 넘겨서는 안 된다. 결함의 위험과 수용 권한을 구분한다.

구분운영 수용 판단필수 조치
Critical원칙적으로 No-Go원인 해결·재시험·책임자 승인
High중대한 업무/보안/복구 영향 시 No-Go위험 평가와 통제 확인
Medium업무 영향이 제한적이면 조건부 검토Owner·기한·완화책·재검증
Low운영 수용 가능 여부 개별 판단백로그·정기 검토

심각도 분류는 고객 정책과 계약을 따른다. 조건부 수용은 위험이 사라졌다는 뜻이 아니라 책임자가 위험을 명시적으로 수용했다는 기록이다.

23.12 운영 인계 체크리스트

  • 실제 설치 상태와 CMDB·구성도가 일치한다.
  • 운영팀이 읽기 전용 상태 점검과 알람 해석을 수행했다.
  • 서비스별 백업·복구 실증 결과와 RTO/RPO가 첨부되었다.
  • 운영 계정과 비밀정보는 승인된 보관체계로 인계되었다.
  • 보안 예외·미해결 결함의 소유자와 만료일이 지정되었다.
  • 변경 승인·롤백·비상연락 체계가 확정되었다.
  • FAT/SAT 증거가 검색 가능하며 접근통제·보존기간이 정해졌다.
인계 완료의 의미

운영팀이 정상 상태를 확인할 뿐 아니라 장애 발생 시 누구에게 무엇을 요청하고 어떤 근거로 복구 성공을 판단하는지 설명할 수 있어야 한다.
