공개 교육용 참조 설계

고객 식별자·내부 주소·비밀정보를 포함하지 않는다. 실제 적용은 제품 지원 사양, 보안 정책 및 변경 승인에 따른다. 수치와 SLO는 교육용 가정이다.

27.1 플랫폼은 별도의 업무 서비스다

자동화 플랫폼도 Controller, Collector, Policy Engine, Job Queue, Audit Store, 사용자 인증으로 구성된 독립 서비스다. 업무 ERP·UC가 정상이어도 자동화 플랫폼 장애로 운영 가시성이 사라질 수 있다. 따라서 플랫폼 가용성과 ERP·UC 가용성을 혼동하지 않는다.

27.2 참조 아키텍처

운영자 / SSO / MFA
       │
   API Gateway ── Audit Store (append-only)
       │
 Controller (stateless, 2+ replicas)
       ├── Policy Engine (versioned, deny-by-default)
       ├── Job Queue (durable, bounded)
       └── Evidence Store (encrypted, retention)
                    │
           Collector / Agent (read-only)
                    │
            ERP / UC / DB / K8s

별도 승인 → Action Runner (short-lived credentials)
              → 대상별 allowlist → 검증/원복

진단 경로와 변경 경로를 네트워크·계정·권한으로 분리한다. 수집 장애가 곧 실행 권한 상승으로 이어져서는 안 된다.

27.3 구성 요소별 책임

컴포넌트책임장애 시 원칙
Controller작업 상태·승인 연결새 변경 실행 중단, 조회는 가능하면 유지
Collector읽기 전용 증거 수집UNKNOWN 판정, 정상으로 간주 금지
Policy Engine서명된 정책 평가Fail closed, 마지막 승인 정책의 무제한 재사용 금지
Queue작업 내구성·재시도중복 방지·만료 검증 후 재개
Runner승인된 조치만 실행권한 폐기·중단·사후 검증
Audit Store증거·승인·실행 추적감사 기록 불가 시 변경 중단

27.4 HA와 장애 도메인

Controller 복제만으로 HA가 완성되지 않는다. 큐, 상태 DB, 인증, DNS, 감사 저장소가 단일 장애점인지 확인한다. 서로 다른 노드·가용 영역에 배치하되 quorum, fencing, split-brain 방지 및 복구 순서를 검증한다. ERP 운영망과 관리망의 장애 전파 경계를 정의한다.

27.5 장애 시 안전한 성능 저하

수집 실패는 UNKNOWN, 정책 서버 불가 또는 승인 검증 실패는 DENY, 감사 저장 실패는 WRITE BLOCK으로 처리한다. 이미 실행 중인 변경은 사전 정의된 중단 지점에서 안전하게 정지하고 운영자에게 상태를 표시한다. 자동 재시도는 멱등성이 검증된 작업에만 허용한다.
