공개 교육용 참조 설계

실제 OmniEsol 설치 명령 또는 지원 사양이 아니다. 제품 공식 지원 문서, 보안 정책 및 변경 승인을 우선한다. 모든 주소와 수치는 교육용 예시다.

34.7 RHEL 준비와 변경 범위

OS 설치와 OS 구성은 구분한다. 기존 서버에 접속하는 SSH 실행기는 베어메탈 OS 설치 자체를 대체하지 못한다. 신규 서버 OS 프로비저닝은 PXE, 이미지 또는 관리 API 등 별도 승인 경로가 필요하다.

cat /etc/os-release
uname -r
lsblk -f
findmnt
free -h
getenforce

설치 전 조사값을 기록하고 지원 버전과 비교한다. 파일시스템 생성, 파티션 변경, 재부팅, 방화벽 변경은 별도 위험 분류 및 승인을 적용한다. 모든 환경에 동일한 sysctl 값을 강제하지 않는다.

34.8 Oracle Database 설치 단계

Oracle 소프트웨어 설치와 데이터베이스 생성은 독립 단계다. 승인된 패치 레벨, OS 패키지, Oracle Home, Inventory, 데이터 경로, 문자 집합, 라이선스 및 백업 정책을 먼저 확인한다. 공식 silent 설치 방식과 검토된 응답 파일을 사용하되 비밀값은 실행 시 안전한 채널로 주입한다.

단계완료 증거
소프트웨어Inventory 및 버전 확인
DB 생성의도한 DB 식별자, OPEN 상태
Listener서비스 등록과 AP 측 연결
백업 준비승인된 정책 및 복구 검증 계획

기존 Oracle Home이나 DB가 감지되면 신규 설치로 덮어쓰지 않고 별도 마이그레이션 또는 재개 경로를 선택한다.

34.9 ERP WEB/WAS와 패키지

DB 접속 및 스키마 준비를 확인한 후 WAS 도메인과 WEB 설정을 배포한다. 패키지의 스키마 변경은 공급자가 지원하는 설치 도구로 수행한다. 정상 프로세스와 업무 정상성은 다르므로 로그인·조회·교육용 저장 검증을 별도 수행한다.

ss -lnt
systemctl --failed
curl --fail --silent --show-error --max-time 15 \
  --cacert approved-ca.pem https://erp.example.invalid/health

health 경로는 예시이며 실제 지원 경로로 변경한다. 인증서 오류를 무시하는 방식으로 성공 판정을 내리지 않는다.

34.10 Kubernetes 기반 UC

클러스터 생성, CNI와 CSI, Ingress, Registry 인증, 의존 서비스와 UC 워크로드 배포를 분리한다. 패키지 설치 순서는 해당 지원 문서를 기준으로 정의한다. PVC 바인딩, Pod 배치 실패, 인증서, 이미지 pull을 확인한다.

kubectl get nodes
kubectl get pods -n example-uc
kubectl get pvc -n example-uc
kubectl get events -n example-uc --sort-by=.metadata.creationTimestamp
kubectl rollout status deployment/example-web -n example-uc --timeout=120s

명령은 조회 예시이며 namespace와 deployment는 가상 값이다. rollout 성공만으로 메일·메시지·파일 등 전체 UC 기능의 정합성을 보장하지 않는다.

34.11 폐쇄망과 설치 패키지 관리

외부 인터넷 없이 설치할 수 있도록 승인된 RPM 저장소, 이미지, 바이너리, 패치, CA 체인과 문서를 버전별 번들로 관리한다. 이미지 태그 대신 digest를 고정하고 대상 CPU 아키텍처와 OS 버전을 검증한다. 외부망 연결을 임시로 열어 설치하는 것을 기본 절차로 삼지 않는다.

번들 크기와 동시 전송으로 발생하는 네트워크·디스크 병목을 고려한다. 현장 캐시는 효율적이지만 변조와 오래된 버전 사용 위험이 있어 재검증 및 수명주기 정책이 필요하다.

34.12 설치 완료와 업무 검수의 차이

검수 영역확인 항목
인프라승인 구성, 자원, 연결 경로
DB서비스 접속, 상태, 백업 준비
ERP로그인, 조회, 승인된 시험 거래
UC메시지, 파일, 실시간 연결, 해당 시 메일
통합SSO, 연계, 권한, 로그, 모니터링

업무 시험은 테스트 계정과 합성 데이터로 수행한다. 설치기는 증거를 제공하고 업무 소유자가 수용 여부를 판단한다. 지원 문서에 없는 성공 기준을 임의로 제품 보증 조건으로 사용하지 않는다.
