독립 교육용 참조 원고

OmniEsol의 공식 설치·지원 사양을 대신하지 않는다. 구성 예시와 명령은 학습 및 검토용이며, 실제 고객 환경에서는 계약 범위·검증 버전·보안 정책·변경 승인을 확인한다.

5.1 설치 전에 요구사항부터 확정한다

설치 지연의 흔한 원인은 설치 명령을 몰라서가 아니라, 구축 범위와 전제조건이 서로 다르게 이해된 상태에서 작업이 시작되기 때문이다. 예를 들어 '외부 접속 허용'이라는 문구에는 모바일 앱만 허용한다는 뜻도, 모든 웹 포털을 외부 공개한다는 뜻도 들어갈 수 있다.

질문명확하게 기록할 답
서비스 도입 범위ERP/UC/협업/모바일/외부 연계의 포함 여부
사용자 유형내부 사용자, 외부 사용자, 협력업체, 관리자
외부 접근 정책허용 단말·URL·API·인증 방식·시간대
데이터 복구백업 주기, 보존기간, 실제 복원 책임
운영 준비로그/모니터링/상주 또는 원격 장애 대응

설치계획서에는 요구사항뿐 아니라 누가, 언제, 어떤 근거로 승인했는지를 함께 기록한다.

항목확인 방법합격 기준 예시

계정/권한승인된 사용자·sudo 정책 검토개인 계정 분리·최소 권한
cat /etc/os-release
uname -r

예시 명령은 조회 목적이다. 제품에 필요한 정확한 파일시스템, 필수 패키지, sysctl, ulimit는 버전별 설치 표준에서 확인하고, 임의 변경은 작업 승인 후 수행한다.

5.3 DNS·방화벽·인증서 사전 확인

설치 전 네트워크 검증은 '핑이 된다'는 확인으로 끝나지 않는다. 주소 해석과 TCP 연결, TLS 핸드셰이크, 호스트 이름 기반 라우팅, 애플리케이션 정상 응답을 단계별로 확인해야 한다.

정보예시 검증
FQDN내부·외부에서 기대한 IP를 응답하는가?
TLS 인증서SAN, 체인, 만료일, SNI가 일치하는가?
방화벽출발지/목적지/방향/프로토콜/포트의 근거가 있는가?
ProxyHost/Forwarded 헤더와 WebSocket/SSE 등 필요한 프로토콜이 지원되는가?
모바일 접근앱의 실제 호출 경로를 검증했는가?

외부 DNS를 사용하도록 전환하면 내부 서비스가 외부 공인 주소로 향하는 구간에서 Hairpin NAT나 접근 정책 문제가 발생할 수 있다. 임시 hosts 변경으로 해결한 경우에도 운영 대책으로 고정하지 말고 원인 경로를 문서화한다.

5.4 Database·Storage·Backup 준비

DB 용량은 데이터 파일의 현재 크기뿐 아니라 증가량, 인덱스, 로그, 백업 저장 공간과 복원 시간을 포함해서 판단한다. Oracle 환경에서는 Redo/Archive 사용량과 백업 정책, 스토리지 지연을 함께 검토한다. DB의 상세 설치·패치/라이선스는 계약된 지원 기준을 따른다.

대상설치 전 점검자주 빠지는 항목
DB인스턴스/스토리지/로그·연결 정보백업 복원 시험과 로그 공간
파일 저장소용량·권한·스냅샷·백업첨부파일 증가와 복구 순서
Redis/캐시지속성 요구·용도·메모리 상한세션 소실 시 사용자 영향
검색인덱스/데이터 구분과 재생성 계획원본 데이터 복원 후 재색인 시간
복구 원칙

스냅샷, 백업 성공 로그, 복원 성공은 각각 다른 증거다. 정기적으로 격리된 환경에서 업무 수준의 복구를 확인한다.

5.5 Kubernetes 배포 사전 검증

  • API Server 접근과 RBAC 권한이 작업 범위에 맞는가?
  • 노드 OS·컨테이너 런타임·Kubernetes 버전이 검증된 조합인가?
  • Pod CIDR/Service CIDR이 고객 사내 주소대역과 중복하지 않는가?
  • LoadBalancer/Ingress 구현과 IP 할당·DNS 등록 정책이 정의됐는가?
  • 영속 볼륨, StorageClass, 회수 정책, 백업 및 복원 경로가 준비됐는가?
  • 사설 Registry/오프라인 설치 시 이미지 출처와 무결성 확인 경로가 있는가?
  • Pod Security, NetworkPolicy, Secret 관리와 감사로그가 정의됐는가?
kubectl get nodes -o wide
kubectl get storageclass
kubectl get ingressclass
kubectl get namespaces
kubectl -n example-uc get resourcequota,limitrange

클러스터 Ready 여부만이 아니라 DNS, CNI, Storage, Ingress, Registry까지 설치 전 점검해야 Pod 배포 이후 장애를 줄일 수 있다.

5.6 Go/No-Go 및 책임 구분

통과 기준GoNo-Go 또는 조건부 승인
버전/라이선스공식 검증 조합 확인지원 여부 미확정
망·TLS내외부 필수 경로 테스트 성공외부 URL/인증서/방화벽 미준비
데이터백업·복구 책임/목표 합의복구 가능성 검증 없음
보안접근권한, 계정, 포트 승인공용 관리자·승인 없는 예외
운영장애 연락체계·모니터링 준비인수인이 불명확

조건부 승인 시에는 위험 항목, 예상 영향, 소유자, 해소 기한, 되돌림 기준을 명시해야 한다. '추후 확인'만 적어두면 운영 단계에서 책임 논란이 생긴다.
