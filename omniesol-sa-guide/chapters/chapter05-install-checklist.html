공개 기술서 이용 안내

독립 교육용 초안으로서 제조사의 공식 설치·지원 매뉴얼이 아니다. 실제 구축에서는 계약된 제품 범위, 공식 호환 버전, 고객 보안 정책과 승인된 변경절차를 우선한다.

5.1 설치보다 먼저 합의할 사항

서버가 준비되어도 설치가 시작되지 않는 경우가 많다. OS와 DB 버전, 네트워크, 방화벽, DNS, 설치 권한, 스토리지 구조, 제품 라이선스가 연결되어 있기 때문이다. SA는 설치 담당자가 당일 현장에서 처음 문제를 발견하지 않도록 사전 점검을 선행한다.

검토 대상요구할 자료승인 주체 예시
서비스 범위ERP/UC/모바일/외부접속/연계 목록고객 업무 책임자
인프라CPU·RAM·Disk·OS·VM/물리 사양인프라 운영팀
지원 Matrix제품·WAS·JDK·DB·K8s 버전제품 기술지원/아키텍트
네트워크FQDN, VIP, DNS, 라우팅, 방화벽네트워크·보안팀
복구/운영백업·모니터링·원격지원·RACI운영 및 보안 책임자

5.2 서버와 OS 사전점검

운영체제 이름과 버전이 같아도 커널·패키지·시간 동기화·리소스 제한·마운트 옵션이 다르면 패키지 설치와 서비스 성능이 달라질 수 있다. 공식 요구 사양과 비교할 때는 단순 서버 스펙 숫자뿐 아니라 설치 이미지를 어떤 기준으로 구성했는지 확인해야 한다.

# 읽기 전용 기본 점검 예시 (RHEL 계열)
cat /etc/os-release
uname -r
lscpu
free -h
lsblk -f
df -hT
timedatectl status
ip -br address
ip route
ss -lnt
항목검증 기준
CPU·MemorySizing 가정과 실제 인식 자원 일치
Disk/LayoutDB 데이터·Redo·Archive·백업 경로 구분
시간NTP/chrony 동기화, 타임존 일치
서비스 계정최소 권한, sudo 범위, 소유자 분리
보안 정책SELinux/방화벽 정책 적용 상태와 예외 승인
버전제품 공식 호환성 기준 확인
주의

실습 편의를 위해 SELinux나 호스트 방화벽을 무조건 비활성화하지 않는다. 필요한 접근만 보안 담당과 승인받아 열어야 한다.

5.3 DNS·TLS·방화벽 검증

내부 사용자, 외부 사용자, 모바일, 백엔드 연계는 접속 경로가 다를 수 있다. 동일 FQDN을 사용하더라도 Split DNS 환경에서는 서로 다른 IP로 해석될 수 있다. SNI, 인증서 체인, LB/Proxy 리다이렉트까지 포함한 요청 흐름 검증이 필요하다.

정보필요한 내용
FQDN내부/외부에서 사용할 이름과 IP 매핑
TLS인증서 SAN, 유효기간, 체인, 종료 위치
방화벽출발지·목적지·포트·프로토콜·소유자
ProxyHost 전달, URL rewrite, WebSocket/SSE, Timeout
DB 접근WAS·UC 컴포넌트에서 필요한 최소 포트

5.4 DB·스토리지·백업 준비

DB 설치 디스크의 여유 공간만 확인해도 충분하다는 생각은 위험하다. 데이터 파일, 트랜잭션 로그, Archive, 임시 영역, 백업 파일은 목적과 성장 속도가 다르다. 가상화·SAN/NAS 환경에서는 물리 디스크 공유로 인한 지연도 발생할 수 있다.

  • DB 데이터·로그·백업의 용량, 증가율, 저장소 성능 요구를 구분한다.
  • 백업 파일이 존재하는지뿐 아니라 시험 복구에 필요한 키·권한·도구·보관 정책을 확인한다.
  • DBMS 라이선스와 CPU·가상화 적용 범위를 계약 조건으로 검증한다.
  • 복구 시험에서 실제 RTO와 데이터 정합성을 확인한다.
절대 금지

계정 비밀번호, DB 연결 문자열, 백업 암호, 인증서 개인키를 설치 결과서나 공개 GitHub 저장소에 포함하지 않는다.

항목확인 사항미충족 시 위험

설치 순서는 환경마다 다르지만 공통 전제는 같다. Network, DNS, Storage, Registry, 권한이 준비되지 않은 상태에서 서비스만 배포하면 Ready 실패 또는 재배포 작업이 반복된다.

5.6 설치 승인: Go/No-Go

설치 시작은 “모두 준비되었다”는 구두 답변이 아니라 검증 증거를 포함한 승인 상태여야 한다.

점검 분야GO 기준NO-GO 예
지원성공식 버전/구성 확인미검증 OS·WAS·DB 조합
리소스Sizing·볼륨·백업 공간 확인업무 피크/N+1 부족
접속DNS/TLS/Firewall 사전 시험 통과내·외부 도메인 불일치
보안운영 계정·비밀 관리·접근권한 승인공용 관리자 계정 공유
복구백업·복원 절차/담당자 지정복원 테스트 계획 없음
운영점검표·로그·모니터링·이관 역할 확정장애 책임 및 연락 경로 부재

예외적으로 승인되지 않은 항목을 보유하고 진행해야 한다면 이슈 ID, 영향, 임시 통제, 책임자와 해소 기한을 남겨야 한다. 고객 서명 없는 암묵적 예외는 운영 리스크를 키운다.
