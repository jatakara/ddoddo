22.6 PoC는 시연이 아니라 가설 검증

PoC는 화면이 열린다는 것을 보여주는 데 그치지 않는다. 업무 피크·장애·보안 조건에서 서비스 목표를 만족하는지 반증 가능한 가설로 검증한다. 테스트 환경의 버전, 데이터량, 네트워크, 부하 발생 위치를 고정한다.

통제패키지·DB 데이터량·TLS·테스트 시간대

22.7 동시 사용자와 RPS를 구분

등록 사용자 수와 동시 진행 요청 수는 다르다. 안정 상태에서 Little's Law(L=λW)는 평균 처리율 λ와 평균 체류시간 W의 관계를 설명한다. 서버 사양을 이 식 하나로 결정하지 않는다.

가상 예시:
λ = 80 requests/sec
W = 0.4 sec
L = 80 × 0.4 = 32 (평균 진행 중 요청)
주의: 32는 동시 로그인 사용자 수가 아님

로그인10%

22.9 측정과 재현성

  charter.md       # 가설·합격 기준
  environment.yaml # 버전·가상 사양
  load-profile.json
  measurements.csv # 시각·p95·오류율·DB Wait
  failures.md      # 실패 원인 포함
  decision.md      # ADR 연결

테스트 결과는 평균값만이 아니라 p95/p99와 오류율을 같은 시계열로 비교한다. 비밀번호·토큰·내부 IP·실고객 데이터는 공개 자료에 포함하지 않는다.

22.10 Go/No-Go 판정

  • 동일 조건에서 대안을 비교했는가?
  • 지원성·보안·복구 목표를 필수 통과로 설정했는가?
  • 실패한 시나리오도 기록했는가?
  • 노드 장애 후 업무 처리와 N+1 용량을 확인했는가?
  • 시험 스크립트와 운영자 인수인계 문서가 있는가?

PoC 결과는 ADR과 위험 등록부의 증거로 연결한다.
