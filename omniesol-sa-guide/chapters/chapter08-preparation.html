8장. 설치 전 인프라 준비

설치 명령보다 중요한 것은 사전 준비의 완성도다. 서버·네트워크·보안·데이터·운영 책임을 확인하고 설치 가능 여부를 증거로 판단한다.

학습 목표와 적용 범위

이 장을 마치면 고객사 IT 담당자, PM, SA가 무엇을 누가 언제까지 어떤 증거로 확인해야 하는지 설명할 수 있다.

이 장은 일반적인 엔터프라이즈 인프라 점검 방법론이다. 공식 OmniEsol 지원 버전, 필수 포트, 최소 사양과 라이선스 조건을 대체하지 않는다. 실제 구축은 제품 공식 검증 기준을 우선한다.

8.1 사전 준비 프로세스

업무 범위 → 아키텍처 → 서버/OS/스토리지 준비
       → DNS/네트워크/보안 정책 → DB/백업
       → 증적 수집 → Go/No-Go 승인 → 설치

서버에 SSH로 접속할 수 있다는 사실은 설치 준비 완료를 의미하지 않는다. 사용자 요청이 DNS, TLS, 프록시, AP, DB를 거쳐 정상적으로 응답하는 전체 경로를 검증해야 한다.

8.2 서비스 범위와 책임(R&R)

구분사전 확정 사항증적
도입 범위ERP/UC 단독, 통합형, 분리형; 운영·개발·DR 구분서비스 범위표·구성도
사용자 접속내부/외부/모바일, 도메인, VIP, 인증 방식접속 경로도
서버·OSCPU, RAM, OS 지원 버전, 계정, 시간 동기화서버 점검표
네트워크·보안DNS, NAT, L4/L7, 방화벽, WAF, TLS정책 승인·통신 테스트
DB·백업DB 버전·계정·스토리지, RTO/RPO, 복구 절차DB 점검·복원 시험
제품검증 패키지·설치 순서·기능 테스트설치계획서

작업 수행자, 검토자, 최종 승인자를 분리하고 고객사·구축사·미들웨어사 간 경계를 문서화한다. 미결 항목에는 담당자와 완료 기한을 지정한다.

8.3 서버·OS·가상화

항목확인 기준
CPU/메모리7장 Sizing 산정값, 가상화 오버커밋, 장애 시 여유 용량
스토리지OS/DB/로그/백업 공간과 IOPS·지연시간, 증설 계획
OS공식 지원 배포판·패치 수준, 호스트명, NTP, DNS
계정설치·운영 계정 분리, 최소 권한, 접근 기록
가용성호스트·전원·네트워크·스토리지의 단일 장애점

VM 스냅샷은 장기 백업의 대체재가 아니다. 서버 이중화도 스토리지나 인증 경로가 단일 장애점이면 서비스 가용성을 보장하지 못한다.

8.4 네트워크 접속 경로

외부 사용자 → 공인 DNS → WAF/L7 → 중계 WEB → 내부 AP → DB
내부 사용자 → 내부 DNS → 내부 VIP/WEB → 내부 AP → DB
                                      └→ UC(별도 도메인/인증)

내부 ERP 화면이 열려도 iframe으로 불러오는 UC 메뉴가 별도 도메인이라면 UC 경로를 별도로 확인해야 한다.

항목질문
주소VIP, NAT 전후 IP·포트, 라우팅·응답 경로가 일치하는가?
프록시TCP 전달인지 HTTP Reverse Proxy인지, TLS 종료 위치는?
헤더Host, X-Forwarded-For/Proto 전달과 신뢰 경계는?
장기 연결WebSocket·SSE·업로드의 timeout, buffering을 검증했는가?

8.5 DNS·TLS·인증

내부 PC는 내부 DNS를 사용하고 외부 도메인 조회는 내부 DNS의 Forwarder/재귀 정책을 검토한다. 공용 DNS를 보조 DNS로 무분별하게 추가하면 내부 전용 레코드가 불안정해질 수 있다. Split-horizon DNS는 내부/외부 조회 결과를 각각 기록한다.

영역확인 항목
DNSFQDN, VIP·공인 IP, TTL, 내부·외부 조회 결과
TLS인증서 SAN, 만료일, 체인, TLS 종료 지점
인증SSO 리다이렉트, 쿠키 SameSite/Secure/Domain
브라우저CSP frame-ancestors, X-Frame-Options, CORS, iframe 정책
프록시Host/Proto 헤더와 HTTPS 리다이렉트 일관성

ERP 화면은 열리지만 UC 메뉴만 보이지 않는다면 DNS → TCP/TLS → HTTP → 브라우저 개발자 도구 → 인증 상태 순으로 분석한다.
