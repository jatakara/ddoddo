17.1 업무 자산에서 출발하는 보안 설계

보안 설계는 방화벽 포트를 닫는 작업이 아니다. 업무 자산 → 위협 → 통제 → 검증 증거를 연결하는 과정이다. ERP의 거래·인사 데이터와 UC의 메일·메시지·첨부파일은 노출 범위와 복구 목표가 다르다. 보호 수준은 데이터 분류와 업무 영향에 맞춰 결정한다.

보호 목표질문검증 증거
기밀성누가 어떤 데이터를 읽고 반출할 수 있는가?권한 Matrix, 데이터 분류, 암호화
무결성승인·전표·메시지가 위변조 없이 처리되는가?업무 인가, DB 감사, 정합성 시험
가용성보안장비·인증장애 시 업무를 복구할 수 있는가?WAF/IdP/LB 장애 시험, RTO
추적성누가 언제 접근·변경했는가?감사로그, 변경 승인, 시각 동기화
적용 범위

이 장은 공개 보안 표준과 일반적인 ERP·UC 인프라 참조 설계를 다룬다. 특정 OmniEsol 버전의 필수 포트·기본 설정·지원 구성을 단정하지 않는다. 공식 지원 Matrix와 고객 정책을 우선한다.

17.2 자산 인벤토리와 데이터 흐름

IP·CPU 목록만으로 공격 표면을 파악할 수 없다. FQDN, 서비스 계정, API 토큰, 인증서, DB 스키마, 파일 저장소, 백업, 이미지 저장소, 운영 접속 경로까지 자산으로 관리한다.

자산위험통제
ERP 업무 DB비인가 조회·변조·복구 실패DB 최소 권한, 감사, 암호화, 복원 시험
UC 메시지·파일정보 유출·삭제서버 측 인가, 파일 검사, 보존·백업
SSO 토큰·세션세션 탈취·재사용서명·대상·만료 검증, 로그 마스킹
컨테이너 이미지취약 라이브러리·변조출처·무결성·취약점 점검
운영 로그비밀정보·개인정보 노출수집 최소화·보존·접근 통제
내부망 자동 신뢰 금지

내부 네트워크도 서비스 신원·업무 인가·최소 접근·감사를 적용한다. 네트워크 위치만으로 신뢰하지 않는 원칙은 NIST SP 800-207 Zero Trust의 핵심이다.

17.3 외부·내부 접속 경계와 분리형 구조

외부 사용자에게 UC만 허용하고 ERP를 내부 전용으로 운영한다면 메뉴 숨김이 아니라 API·인증·첨부파일·정적 리소스의 실제 호출 경로를 검증해야 한다. QR 인증이나 모바일 연계는 최초 인증과 후속 API의 FQDN이 다를 수 있으므로 기능별 호출 흐름을 기록한다.

경계검토 질문대표 실패
Split DNS내·외부에서 FQDN이 어디로 해석되는가?특정 망에서만 실패
WAF/ProxyHost·URI·메서드·업스트림 제한이 있는가?내부 API 노출
TLS 종단Proxy 뒤 구간에도 암호화가 필요한가?인증서 오류·보호 누락
API 인가서버가 매 요청의 업무 권한을 확인하는가?UI 우회로 비인가 접근
관리망SSH·DB·K8s API가 사용자망과 분리되는가?관리 포트 외부 노출
Trade-off

공통 WAF/LB는 운영과 비용에 유리하지만 공통 장애 도메인을 만든다. 독립 진입점은 격리에 유리하지만 DNS·인증서·운영 복잡도가 증가한다. 13장 분리형 연계를 함께 참고한다.

17.4 사람·서비스 계정의 최소 권한

최소 권한은 단순히 읽기 권한을 주는 것이 아니라 업무에 필요한 작업·대상·기간을 한정하는 원칙이다. 운영자 계정과 WAS·DB·Kubernetes ServiceAccount의 발급·회수 정책을 분리한다.

주체권장 통제피해야 할 관행
일반 사용자직무 기반 RBAC, 정기 권한 검토광범위 관리자 권한
운영 관리자개인별 계정·MFA·접속 감사공유 root/admin
긴급 관리자비상 사용 승인·사후 감사상시 사용하는 비상 계정
WAS→DB필요한 스키마·작업만 허용DBA/SYS급 업무 접속
K8s ServiceAccount전용 SA, 최소 API 권한default SA에 cluster-admin
외부 API호출 대상·수명·범위 제한무기한 전역 토큰

퇴사·부서 이동·연계 종료 시 개인 토큰, API 키, 인증서도 함께 회수되는지 확인한다.

17.5 SSO·세션·모바일 인증

인증(Authentication)은 신원 확인이고 인가(Authorization)는 업무 권한 판단이다. SSO는 로그인 경험을 개선하지만 모든 API를 자동 허용하지 않는다.

요소검증주의
세션 쿠키Secure·HttpOnly·SameSite·Domain·PathCross-site 연계와 CSRF 방어 함께 검토
토큰서명·issuer·audience·만료·철회로그·URL에 원문 노출 금지
SSO시간 동기화·리다이렉트·로그아웃모바일/도메인별 재현
QR 인증1회성·짧은 만료·재사용 방지·세션 결속스캔 대상·승인 주체 검증
API 인가서버 측 역할·객체 권한화면 메뉴 숨김은 보안 아님
User-Agent기기별 UI 분기위조 가능하므로 보안 인증 수단 아님
User-Agent의 한계

클라이언트가 User-Agent 문자열을 바꿀 수 있다. 편의 기능 분기에는 사용할 수 있지만 외부 접근을 허용·차단하는 유일한 보안 기준으로 삼지 않는다.

17.6 통신 흐름 Matrix와 위협 모델

포트 목록에는 업무 목적·출발지·목적지·담당자·검증 증거가 포함되어야 한다. 다음은 실제 제품 필수 포트가 아닌 논리 예시다.

흐름목적검증 증거
사용자 → 공개 ProxyHTTPS 업무 접근외부 접속 시험·Proxy 로그
Proxy → UC API협업 요청 전달라우팅·인가 로그
ERP WAS → ERP DB업무 트랜잭션DB 감사·정합성
UC API → ERP API승인된 연계호출 ID·양측 인가
관리망 → 서버/K8s유지보수MFA·접속 감사
  • 외부 API 노출, 토큰 유출, 관리자 오남용, DB 데이터 손상, 공통 WAF 장애를 위협 시나리오로 등록한다.
  • 각 위험에 예방·탐지·복구 방법과 잔여 위험 승인자를 연결한다.
  • 허용 업무 성공 시험과 금지된 접근의 거부 시험을 함께 수행한다.
