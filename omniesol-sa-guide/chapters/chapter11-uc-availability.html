11장 2부. UC 접속과 고가용성

11.5 접속 경로와 브라우저 검증

사용자 접속은 DNS, 네트워크 경계, 로드밸런서, 라우팅, 애플리케이션 인증을 차례로 통과한다. 화면이 표시되더라도 일부 API 또는 협업 기능은 별도로 실패할 수 있다.

계층확인 항목
DNS내부·외부 네트워크의 도메인 응답이 설계와 일치하는지 확인
TLS인증서 호스트명, 인증서 체인, 종료 위치, 갱신 책임 확인
프록시호스트·경로 라우팅, 연결 유지 시간, 업스트림 상태 확인
인증SSO 연계 주소, 쿠키 범위, 리다이렉트, 시간 동기화 확인
브라우저개발자 도구에서 실패한 요청, 응답 코드, 프레임 허용 정책 확인

진단은 증상 재현, 실패 요청 식별, 서버 로그 대조, 수정 전후 검증 순서로 진행한다. 특정 계층만 확인하고 원인을 단정하지 않는다.

11.6 고가용성과 장애 격리

동일한 노드에 복제본이 집중되면 단일 노드 장애로 서비스가 중단될 수 있다. 워크로드를 서로 다른 장애 영역에 분산하고, 노드 장애 시 잔여 용량을 확보해야 한다.

설계검증 기준
Replica 분산노드와 가용 영역별 배치 확인
Readiness준비되지 않은 인스턴스에 신규 요청이 전달되지 않는지 확인
계획된 유지보수PodDisruptionBudget과 노드 배수 작업 시험
데이터 계층DB·파일 저장소의 장애 전환과 복원 시험
접속 계층로드밸런서·Ingress 인스턴스 장애 시험

고가용성은 복제본 수만으로 성립하지 않는다. 네트워크·저장소·운영 체계까지 함께 검증한다.
